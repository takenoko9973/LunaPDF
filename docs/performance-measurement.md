# 性能測定手順

設計書15.4の性能目標を、同じ入力と操作列で再現して記録する。ここには実測値を記入せず、測定時に結果欄を埋める。

## 固定fixtureと操作列

- fixture: 50–100ページの通常PDFを毎回使用する。20タブ測定では同じ内容を持つ別パスの20ファイルを用意し、各PDFのページ数、ファイルサイズ、画像の有無、checksumをmanifestへ記録する。同じパスは既存タブへ集約されるため20タブ測定には使わない。
- cold: 測定環境で再現可能な方法によりアプリとOSのファイルキャッシュを空にし、その方法を記録してから最初のPDFを開く。キャッシュ状態を確認できない測定はwarmとして扱う。
- warm: アプリを終了・再起動するが、OSのファイルキャッシュは維持して同じPDFを開く。
- 操作列: 起動 → PDFを開く → 最初のページが表示されるまで待つ → 3ページ分スクロール → 検索語を入力してUIの応答を測る → 検索完了を待つ → manifest順に20ファイルを開く。
- 1/10/20タブの各時点で、非アクティブタブを操作せずにRSSを記録する。

## 記録する値

status表示で直接読める値はアプリの表示値を使い、RSS・フレーム時間・入力遅延は外部計測器で測る。各値はcold/warmを分け、単位を固定する。

| 測定 | 取得方法 | cold | warm | 目標 / 判定 |
| --- | --- | ---: | ---: | --- |
| 起動時間 | プロセス開始からウィンドウ表示までを外部計測 |  |  | 1 s以内を目標 |
| 初回ページ表示 | open操作から最初のページ表示までを外部計測。statusのopen時間は内訳として併記 |  |  | 500 ms以内を目標 |
| 可視タイル完成 | ページ移動から可視タイル完成までを外部計測。statusのrender時間は内訳として併記 |  |  | 基準値を記録 |
| RSS: 1 tab | 外部プロセス計測 |  |  | 推移を記録 |
| RSS: 10 tabs | 外部プロセス計測 |  |  | 推移を記録 |
| RSS: 20 tabs | 外部プロセス計測 |  |  | 安定時512 MiB以内を目標 |
| 最大フレーム時間 | 外部フレーム計測 |  |  | 通常操作で100 ms超の停止なし |
| 検索入力遅延 | 検索中の入力からUI反映までを外部計測 |  |  | 100 ms超の停止なし |
| cache plateau後のRSS推移 | 20タブ操作後に外部計測 |  |  | CPU画像192 MiB、GPU texture 192 MiB、thumbnail 32 MiBの各予算到達後に増加し続けない |

`open`、`render`、`text`、`resident memory` は画面のstatus表示から直接読める。起動時間、初回ページ表示、可視タイル全体の完成、RSS、フレーム時間、検索入力遅延、cache plateauの判定は外部計測が必要である。
