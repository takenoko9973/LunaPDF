# Codex向け LunaPDF 空白パン・自動スクロール カーソル修正指示書

## 位置付け

本書は、次の指示書に基づく実装が完了した後に適用する差分修正指示書です。

```text
docs/tasks/ui-improvement/lunapdf_codex_annotation_interaction_sidebar_followup_instructions.md
```

または、その内容を取り込んだ後継指示書を対象とします。

前段の実装では、少なくとも次が既に実装済みであることを前提とします。

- PDF表示領域内の空白から左ドラッグでパンできる。
- ページ外の灰色背景からもパンを開始できる。
- 文字、注釈、リンク、フォーム、画像などの操作対象上ではパンを開始しない。
- 中ボタン自動スクロールは連続表示でのみ有効。
- 中ボタン自動スクロールの最大速度は`4,800 pt/s`。
- 単一ページ表示では中ボタン自動スクロールを開始しない。

本書では、これらの機能自体を再設計しません。

実装後に確認されたカーソル表示の問題だけを調査し、最小限の修正を行ってください。

## 修正対象の問題

実装後のLunaPDFで、PDF表示領域上のカーソルが継続的に十字形または四方向移動形になり、空白パンの操作状態を正しく表現していません。

期待する動作は、SumatraPDFの文書ドラッグに近い次の表示です。

- パンを開始できる空白上：開いた手。
- 左ドラッグでパン中：閉じた手。
- パン終了後：現在のポインター位置に応じた通常のカーソルへ戻る。
- 中ボタン自動スクロール用の十字または四方向カーソルは、自動スクロール中だけ表示する。

「常に十字カーソルを表示する」状態は仕様ではなく、不具合として扱ってください。

## 作業方針

### 現象を再現してから修正する

次の各状態で、実際にどのカーソルが設定されているか確認してください。

- PDFページ内の文字上。
- PDFページ内の空白上。
- ページ外の灰色背景上。
- リンク上。
- ハイライト注釈上。
- 空白パン中。
- 空白パン終了直後。
- 中ボタン自動スクロール中。
- 中ボタン自動スクロール終了直後。
- 単一ページ表示。
- タブ切替直後。
- ウィンドウのフォーカス喪失と復帰後。

推測だけで修正せず、カーソル決定箇所と状態遷移を確認してください。

### 差分を限定する

今回の対象はカーソル表示と、その残留を引き起こす状態リセットです。

次を行わないでください。

- 空白パンの移動量やスクロール計算の変更。
- テキスト選択判定の再設計。
- ハイライト一覧の変更。
- 注釈編集UIの変更。
- 中ボタン自動スクロールの速度特性の変更。
- 入力アーキテクチャ全体の置換。
- カーソル修正に不要なリファクタリング。

## 1．空白パンのカーソルを手の形にする

### 1.1 パン開始可能な空白

PDF中央表示領域内で、空白パンを開始できる位置へポインターを置いた場合は、次を使用してください。

```rust
egui::CursorIcon::Grab
```

Windows実機では、開いた手として表示されることを確認してください。

対象には次を含みます。

- PDFページ内の空白。
- ページ外の灰色背景。

ただし、PDF中央表示領域内であっても、次の対象上では`Grab`を表示しないでください。

- テキストglyphと、その選択許容範囲。
- 現在のテキスト選択範囲。
- リンク。
- ハイライト注釈。
- PDFフォーム部品。
- 画像。
- その他、独立した操作対象として扱う要素。

### 1.2 空白パン中

左ドラッグによる空白パンが実際に開始された後は、次を使用してください。

```rust
egui::CursorIcon::Grabbing
```

ドラッグ閾値を超える前から`Grabbing`へ変更しないでください。

左ボタンを押しただけで、まだパンが成立していない間は`Grab`を維持してください。

### 1.3 パン終了後

左ボタンを離したフレーム以降は、`Grabbing`を残さないでください。

ポインター位置に応じ、次のいずれかへ直ちに戻してください。

- テキスト上：I-beam。
- リンク上：リンクまたは指示用カーソル。
- 注釈上：既存の注釈用カーソル。
- パン可能な空白上：`Grab`。
- その他：通常の既定カーソル。

パン終了時に強制的に矢印へ固定するのではなく、現在のヒット対象から再評価してください。

## 2．十字カーソルを空白パンへ使用しない

空白パンでは、次を代用しないでください。

```text
Crosshair
AllScroll
Move
Resize系カーソル
```

空白パンの待機状態と実行状態は、必ず`Grab`と`Grabbing`で区別してください。

ページ全体へ一律に`Grab`を設定しないでください。

文字、リンク、注釈などのカーソルを空白パンのカーソルで上書きしないでください。

## 3．中ボタン自動スクロールのカーソルを限定する

### 3.1 動作中

中ボタン自動スクロールが実際に有効な間だけ、四方向移動を示すカーソルを使用して構いません。

egui標準を使用する場合は、次を候補とします。

```rust
egui::CursorIcon::AllScroll
```

`Crosshair`を使用している場合は、その必要性を確認してください。

単なる目印として十字形を使っているだけなら、`AllScroll`へ変更してください。

### 3.2 停止時

次のいずれかが発生した時点で、自動スクロール用カーソルを解除してください。

- 中ボタンで停止した。
- 左クリックで停止した。
- Escapeで停止した。
- 単一ページ表示へ切り替えた。
- 文書タブを切り替えた。
- 文書タブを閉じた。
- PDFを再読込した。
- ウィンドウがフォーカスを失った。
- アプリ終了処理へ入った。
- 自動スクロール状態がエラーまたはキャンセルで終了した。

停止後は、現在のポインター位置に応じてカーソルを再評価してください。

`AllScroll`または十字カーソルを、通常のPDF閲覧状態へ持ち越さないでください。

## 4．カーソル決定の責務を整理する

### 4.1 状態から毎フレーム決定する

カーソルは、過去に設定した値へ依存して残留させず、現在の入力状態とヒット対象から毎フレーム決定してください。

少なくとも次の状態を区別してください。

```text
通常閲覧
テキスト選択候補
テキスト選択中
空白パン候補
空白パン中
中ボタン自動スクロール中
リンク上
注釈上
フォーム操作中
リサイズ操作中
```

### 4.2 優先順位

カーソルの優先順位は、現行の入力責務を確認したうえで、少なくとも次の順序を満たしてください。

1. フォーム編集、リサイズなどの専用操作中。
2. テキスト選択中またはテキスト上。
3. リンク、注釈などのクリック可能要素上。
4. 中ボタン自動スクロール中。
5. 空白パン中。
6. 空白パン開始可能な空白上。
7. 通常の既定カーソル。

実装構造上、4と5の同時成立を許可しないでください。

### 4.3 不要な状態を増やさない

カーソル表示だけのために、同じ入力状態を二重管理しないでください。

既存のパン状態、自動スクロール状態、ヒットテスト結果を再利用してください。

ただし、複数のboolが矛盾して十字カーソルを残す構造になっている場合は、責務を明確にする最小限の状態整理を行って構いません。

カーソル、パン、選択、自動スクロール、注釈編集を一つの巨大な状態型へ統合しないでください。

## 5．標準カーソルで不足する場合

まず、使用中のegui／eframeで次を試してください。

```rust
egui::CursorIcon::Grab
egui::CursorIcon::Grabbing
```

Windows実機で期待した開いた手と閉じた手にならない場合だけ、カスタムカーソルを検討してください。

カスタムカーソルを導入する場合は、次を満たしてください。

- 開いた手と閉じた手を別資産にする。
- DPI倍率に対応する。
- ホットスポット位置を確認する。
- ライトテーマとダークテーマで識別できる。
- Windows配布物へ正しく埋め込む。
- 実行時の外部ファイルを必須にしない。
- SumatraPDFのカーソル資産を無断で複製しない。
- ライセンスと配布条件を作業報告へ記載する。

標準カーソルで十分な場合は、カスタム資産を増やさないでください。

## 6．自動テスト

GUIカーソル画像そのものを自動テストできない場合は、カーソル決定ロジックを純粋関数または同等に検証可能な単位へ分けてください。

少なくとも次をテストしてください。

### 空白パン

- ページ内空白上で`Grab`を返す。
- 灰色背景上で`Grab`を返す。
- ドラッグ閾値未満では`Grab`を維持する。
- パン成立後に`Grabbing`を返す。
- 左ボタン解放後に`Grabbing`を返さない。
- テキスト上でI-beamを優先する。
- リンク上でリンク用カーソルを優先する。
- 注釈上で注釈用カーソルを優先する。
- 選択範囲上で`Grab`を返さない。

### 中ボタン自動スクロール

- 自動スクロール中だけ`AllScroll`または採用カーソルを返す。
- 停止後に`AllScroll`を返さない。
- 単一ページ表示では自動スクロール用カーソルを返さない。
- タブ切替後に自動スクロール用カーソルを返さない。
- フォーカス喪失後に自動スクロール用カーソルを返さない。

### 状態遷移

- `Grab`から`Grabbing`へ遷移する。
- `Grabbing`から`Grab`またはI-beamへ戻る。
- `AllScroll`から通常カーソルへ戻る。
- パン状態と自動スクロール状態が同時に有効にならない。
- キャンセル経路でもカーソル状態が残らない。

## 7．手動受入確認

Windows実機で、少なくとも次を確認してください。

### 通常閲覧

- 本文上ではI-beamになる。
- リンク上ではリンク用カーソルになる。
- PDFページ内の空白上では開いた手になる。
- ページ外の灰色背景上では開いた手になる。
- PDF表示領域外では通常のUIカーソルになる。
- 通常閲覧中に十字カーソルが常時表示されない。

### 空白パン

- 空白上で左ボタンを押しただけでは開いた手のまま。
- ドラッグ閾値を超えると閉じた手になる。
- パン中は閉じた手を維持する。
- 左ボタンを離すと閉じた手が消える。
- 空白上で離した場合は開いた手へ戻る。
- 本文上へ移動した場合はI-beamへ戻る。
- リンク上へ移動した場合はリンク用カーソルへ戻る。

### 中ボタン自動スクロール

- 開始すると自動スクロール用カーソルになる。
- 停止すると即座に通常カーソルへ戻る。
- 単一ページ表示へ切り替えると残らない。
- タブを切り替えても残らない。
- ウィンドウを非アクティブにして戻しても残らない。
- 自動スクロール停止後に十字表示が継続しない。

### DPI

可能な範囲で次を確認してください。

- 100%。
- 125%。
- 150%。
- 200%。

標準カーソルを使用する場合も、DPI変更後にカーソル状態が壊れないことを確認してください。

## 9．完了条件

次をすべて満たした時点で完了です。

1. パン開始可能な空白上で開いた手が表示される。
2. 空白パン中に閉じた手が表示される。
3. 空白パン終了後に閉じた手が残らない。
4. 空白パンに十字、`AllScroll`、`Move`を代用しない。
5. テキスト、リンク、注釈などのカーソルを上書きしない。
6. 中ボタン自動スクロール用カーソルは動作中だけ表示される。
7. 自動スクロール停止後に十字または四方向カーソルが残らない。
8. 単一ページ表示、タブ切替、フォーカス喪失後にも残留しない。
9. 前段で実装したパン、選択、自動スクロール速度を壊さない。
10. 自動テストとWindows実機確認の結果を報告する。
11. 未確認の外観を成功扱いしない。

## 10．作業報告

作業報告には次を記載してください。

### 再現

- 十字カーソルが表示され続ける手順。
- どの状態で残留するか。
- 表示モード。
- DPI。
- 使用した入力機器。
- フォーカス、タブ切替、モード切替との関係。

### 原因

- カーソルを決定していたファイルと関数。
- 十字カーソルを設定していた条件。
- 解除されなかった状態。
- 最初に期待値から外れた状態遷移。
- 原因を確認したログ、状態値、失敗テスト。

### 修正

- 使用したカーソル。
- `Grab`、`Grabbing`、自動スクロール用カーソルの決定条件。
- 状態リセット箇所。
- 既存状態の再利用範囲。
- 新しい状態を追加した場合の必要性。

### 検証

- 追加したテスト。
- 実行したコマンド。
- Windows実機で確認したカーソル外観。
- DPI別の結果。
- パン、選択、自動スクロールの回帰結果。

### 未確認事項

- 再現できなかった終了条件。
- 確認できなかったDPI。
- 確認できなかった入力機器。
- 標準カーソルのOS差。
- カスタムカーソルを採用しなかった、または採用した理由。
