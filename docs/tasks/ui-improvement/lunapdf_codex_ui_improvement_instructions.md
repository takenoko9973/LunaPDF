# Codex向け LunaPDF UI・編集機能改善指示書

## 目的

LunaPDFの既存機能を維持しながら、UIをSumatraPDFに近い簡潔な構成へ整理してください。

今回の中心は、タブ上限の撤廃、日本語表示、メニューバーとツールバーの再構成、検索欄の常設、ページ番号入力、Single Page表示のスクロール修正、編集履歴によるUndo、印刷機能、デバッグ表示の分離です。

外観だけを変更するのではなく、既存のタブ管理、セッション復元、PDF描画、文字選択、検索、ハイライト保存との整合性を保ってください。

## 対象リポジトリ

- リポジトリ：`takenoko9973/LunaPDF`
- 既定ブランチ：`main`
- 技術構成：Rust、eframe／egui、MuPDF
- 主な変更候補：
  - `src/app.rs`
  - `src/domain/tabs.rs`
  - `src/pdf/worker.rs`
  - `src/pdf/mupdf_backend.rs`
  - `src/ui/`
  - `src/main.rs`
  - `Cargo.toml`

作業開始時に、実際のリポジトリ構成、`AGENTS.md`、README、既存テスト、未コミット差分を確認してください。

上記の候補と実際の責務が異なる場合は、既存構造を優先してください。

## 作業上の制約

- ユーザーの既存変更を上書きしないでください。
- 本指示に関係しないリファクタリングを行わないでください。
- PDFの保存形式、注釈互換性、レンダリング方式を必要なく変更しないでください。
- LunaPDF専用の別PDFや補助ファイルを生成しないでください。
- 依存関係は、要求を実装するために必要な場合だけ追加してください。
- 依存関係を追加した場合は、理由と影響範囲を報告してください。
- フォントファイルをリポジトリへ追加しないでください。
- 外部のPDFビューアを必須依存にしないでください。
- 実行していないテストや確認を成功として報告しないでください。
- commit、push、PR作成は行わないでください。

## 1．画面構成を整理する

画面上部を次の順序にしてください。

1. メニューバー
2. PDFタブバー
3. アイコン中心のツールバー
4. PDF表示領域
5. デバッグビルドでのみ利用できるデバッグパネル

通常ビルドでは、下部へ性能情報や選択テキストを常時表示しないでください。

### 1.1 メニューバー

上部へ一般的なメニューバーを追加してください。

最低限、次のメニューを設けてください。

#### ファイル

- 開く
- 印刷
- 現在のタブを閉じる
- すべてのタブを閉じる
- 前回のセッションを復元する設定
- 終了

通常のメニュー項目として「保存」は表示しないでください。

`Ctrl+S`による既存の保存機能は維持してください。

#### 編集

- 元に戻す
- 選択テキストをコピー
- ハイライトを作成

「元に戻す」は汎用的な編集履歴へ接続してください。

現時点では編集操作がハイライト作成だけなので、結果としてUndo対象はハイライトだけになります。

UIや内部APIを「ハイライト専用Undo」として固定しないでください。

#### 表示

- サイドバーの表示切替
- 目次
- サムネイル
- 幅に合わせる
- ページ全体を表示
- 連続表示
- 単一ページ表示

必要性が確認できないメニュー項目は追加しないでください。

### 1.2 ツールバー

SumatraPDFの簡潔なツールバーを参考にし、左から次の順で配置してください。

```text
[開く] [印刷] | ページ: [入力欄] / [総ページ数] [前へ] [次へ] | 表示操作 | 編集操作 | 検索欄
```

最低限、次を含めてください。

- PDFを開く
- 印刷
- 現在ページの入力欄
- 総ページ数
- 前ページ
- 次ページ
- サイドバー表示
- 縮小
- 拡大
- 幅に合わせる
- ページ全体を表示
- 連続表示／単一ページ表示
- ハイライト作成
- 元に戻す
- 検索欄
- 前の検索結果
- 次の検索結果
- 検索結果件数

ボタンは原則としてアイコン表示にしてください。

フォルダー、プリンター、サイドバー、目次、サムネイルなどは、絵文字ではなく、単色のベクター描画または埋め込みSVGなど、環境差が出にくい方法を使用してください。

実行時に外部画像ファイルを探索する構成にはしないでください。

### 1.3 ショートカット表示

`Ctrl+S`、`Ctrl+F`、`Ctrl+C`、`Ctrl+Z`などの文字列をツールバーへ常時表示しないでください。

対応するボタンまたはメニュー項目へマウスを重ねたときだけ、ツールチップとして機能名とショートカットを表示してください。

例：

- `PDFを開く（Ctrl+O）`
- `印刷（Ctrl+P）`
- `元に戻す（Ctrl+Z）`
- `選択テキストをコピー（Ctrl+C）`

保存ボタンは設けないため、`Ctrl+S`を表示する専用UIも追加しないでください。

## 2．20タブ制限を撤廃する

ユーザー向けの20タブ上限を完全に撤廃してください。

次を削除または修正してください。

- `MAX_TABS`
- `OpenTabResult::LimitReached`
- 上限到達時のエラー処理
- 20タブを前提とするテスト
- `maximum 20 tabs`などの表示
- `twenty-tab`などのコメントやpanicメッセージ
- セッション復元時に20件で打ち切る処理

同じPDFを再度開いた場合に既存タブを選択する挙動は維持してください。

上限撤廃後も、既存のGPUキャッシュ上限と非アクティブ文書の休止処理は維持してください。

多数のタブを開いた場合に、ハード上限を別の値へ置き換えないでください。

メモリ対策が必要な場合は、古い非アクティブタブを安全に休止し、選択時に再開する既存方針を強化してください。

休止対象に、未保存の変更があるタブを含めないでください。

## 3．日本語表示と入力を修正する

egui上の日本語が欠落または文字化けしないように、CJK対応フォントをフォールバックとして登録してください。

対象には次を含めてください。

- 日本語ファイル名
- メニューバー
- ツールチップ
- サイドバー
- PDFアウトライン
- エラー表示
- 検索欄
- ページ番号欄以外の日本語UI
- 日本語IMEによる検索文字列入力

### 3.1 フォント方針

OSにインストール済みのフォントを使用してください。

フォントバイナリをリポジトリへ同梱しないでください。

候補例：

- Windows：Yu Gothic、Meiryo
- Linux：Noto Sans CJK JP、IPA Gothic
- macOS：Hiragino Sans

特定パスだけを無条件に仮定せず、存在確認と候補のフォールバックを行ってください。

日本語フォントが見つからない場合も起動を失敗させず、英数字の既定フォントで起動してください。

その場合の警告は、通常UIへ常時表示せず、デバッグログまたはデバッグパネルへ記録してください。

PDF本文のフォント処理とeguiのUIフォント処理を混同しないでください。

## 4．検索欄を常時表示する

PDFを開いている間は、検索欄を常時表示してください。

検索欄を開閉するボタンは削除してください。

`SearchState::open`のような開閉状態が不要になる場合は、関連処理を整理してください。

### 4.1 操作

- `Ctrl+F`：検索欄へフォーカスする
- Enter：次の検索結果
- Shift+Enter：前の検索結果
- 前後ボタン：前または次の検索結果
- Escape：検索欄を非表示にせず、フォーカス解除または検索内容と結果のクリアとして扱う

Escapeの具体的な優先順位は、既存の操作と競合しないように決めてください。

推奨順序は次のとおりです。

1. 入力中ならフォーカスを解除する。
2. 入力が残っている状態で再度Escapeを押した場合は、検索文字列と結果を消去する。
3. 検索欄自体は残す。

検索結果件数は、`3 / 18`のように簡潔に表示してください。

検索処理中であることを示す必要がある場合は、小さなスピナーまたは短い進捗表示を使用してください。

## 5．ページ番号を直接入力できるようにする

現在ページを固定ラベルではなく、編集可能な入力欄として表示してください。

表示例：

```text
ページ: [ 4 ] / 5
```

ユーザー向けページ番号は1始まりとしてください。

内部の0始まりインデックスを入力欄へ直接表示しないでください。

### 5.1 確定条件

- Enterで確定する。
- フォーカスを外した場合も、有効な入力なら確定する。
- Escapeで編集をキャンセルし、現在ページ番号へ戻す。
- 空文字、0、負数、非数値、総ページ数を超える値では移動しない。
- 無効な値は、現在ページ番号へ戻す。
- 入力欄にフォーカスがない場合は、スクロールや前後ボタンによるページ移動を反映する。
- 入力中の文字列を、フレーム更新で上書きしない。

ページ入力状態はタブごとに分離してください。

タブ切替時に、別タブの入力途中の値が表示されないようにしてください。

入力確定時は、連続表示と単一ページ表示のどちらでも既存のページ移動処理を使用してください。

## 6．Single Page表示のスクロールを修正する

単一ページ表示でマウスホイールが効かない問題を修正してください。

単にPageUp／PageDownへ置き換えるのではなく、ページ内スクロールとページ遷移を両立させてください。

### 6.1 必須挙動

ページが表示領域より大きい場合：

- 通常のホイールでページ内を上下にスクロールする。
- ページ下端でさらに下へスクロールした場合は、次ページへ移動する。
- ページ上端でさらに上へスクロールした場合は、前ページへ移動する。

ページ全体が表示領域内に収まる場合：

- 下方向のホイールで次ページへ移動する。
- 上方向のホイールで前ページへ移動する。

ページを切り替えた場合：

- 次ページへ進んだときは、新しいページの上端を表示する。
- 前ページへ戻ったときは、新しいページの下端を表示する。
- 先頭ページより前、最終ページより後へ移動しない。

### 6.2 入力競合の防止

- `Ctrl+ホイール`によるズームをページ移動として処理しない。
- 横スクロール入力をページ移動として処理しない。
- 高精度ホイールやトラックパッドの小さな入力で複数ページを連続して飛ばさない。
- ホイール量を蓄積し、閾値を超えた場合だけ1ページ移動する。
- ページ切替直後に同一ジェスチャーの残りで次ページへ進まないようにする。
- ページ番号入力欄や検索欄へ入力中のキー操作を奪わない。

スクロール判定は、現在の`ScrollArea`のオフセット、最大スクロール量、入力deltaを使用し、ページ端に達していない段階ではページ移動させないでください。

## 7．編集履歴とUndoを実装する

Undoをハイライト専用APIとして設計しないでください。

タブごとに、編集操作を表現する汎用履歴を持たせてください。

概念例：

```rust
enum EditAction {
    CreateHighlight {
        page_index: usize,
        annotation_id: AnnotationId,
    },
}
```

実際の型名と識別方法は、既存のMuPDFバインディングとコード構造に合わせてください。

### 7.1 必須要件

- `Ctrl+Z`で最後の編集操作を取り消す。
- メニューバーの「編集 → 元に戻す」とツールバーのUndoボタンも同じ処理を呼ぶ。
- 履歴はタブごとに独立させる。
- Undo可能な操作がない場合は、メニューとボタンを無効化する。
- 保存中、終了確認中、文書ワーカー停止中はUndoを実行しない。
- Undo後に描画キャッシュ、サムネイル、テキストスナップショット、検索結果を適切に無効化する。
- 文書のdirty状態と未保存確認を正しく更新する。
- 元からPDFに存在した注釈を削除しない。

現時点では`CreateHighlight`だけを履歴へ登録してください。

将来の編集操作を追加できる構造にしますが、未要求のRedo、色変更、コメント、注釈移動は実装しないでください。

### 7.2 注釈の識別

「対象ページ内の最後のハイライト」や座標の近似だけで削除対象を推定しないでください。

LunaPDFが作成した注釈だけを確実に識別できる情報を保存してください。

MuPDFバインディングで利用可能な注釈オブジェクト番号、xref、安定した識別子などを調査し、既存注釈と衝突しない方法を採用してください。

保存後に同じ注釈を安全に識別できない場合は、推定削除を行わないでください。

その場合は、保存成功時または再読込時にUndo履歴を無効化する保守的な挙動としてください。

## 8．保存UIを非表示にする

通常のツールバーから、次を削除してください。

- Saveボタン
- `Save (Ctrl+S)`という表示
- 保存方式の常時表示
- 未保存ハイライト数の常時表示

メニューバーにも通常の「保存」項目を追加しないでください。

次は維持してください。

- `Ctrl+S`
- 未保存状態を示すタブ上の簡潔なマーカー
- タブまたはアプリ終了時の保存確認
- 保存失敗時の明確なエラー表示
- PDF保存後の検証処理
- 外部PDFビューアとの注釈互換性

終了時の保存確認ダイアログ内では、「保存」「破棄」「キャンセル」など必要な選択肢を表示して構いません。

## 9．印刷機能を追加する

ツールバーへプリンターアイコンを追加してください。

次の入口は同じ印刷処理へ接続してください。

- プリンターアイコン
- `ファイル → 印刷`
- `Ctrl+P`

PDFが開かれていない場合、文書が読み込み中の場合、保存処理中の場合は無効化してください。

### 9.1 実装方針

外部PDFビューアやSumatraPDFを必須依存にしないでください。

少なくともWindowsで、OSの印刷ダイアログから印刷できるようにしてください。

既存の対応OSとMuPDF Rustバインディングを調査し、利用可能な印刷APIがある場合は優先してください。

直接利用できるAPIがない場合は、Windowsのネイティブ印刷ダイアログと印刷DCを使用し、MuPDFでページをレンダリングして印刷してください。

Windows固有コードは`cfg(windows)`で分離し、Linuxビルドを壊さないでください。

Linux印刷を同じ変更で安全に実装できない場合は、Linuxでは印刷項目を無効化し、ホバー時に未対応であることを明示してください。

未実装のボタンをクリック可能な状態で置かないでください。

### 9.2 印刷対象

- 現在開いているPDFを対象にする。
- OSの印刷ダイアログで指定されたページ範囲を尊重する。
- 部数、プリンター選択、キャンセルを尊重する。
- ページの縦横比を維持する。
- 印刷可能領域へ収めて中央配置する。
- 一度に全文書を巨大な画像へ展開しない。
- ページ単位または適切なストリップ単位で処理し、メモリを制限する。

未保存ハイライトを印刷データへ反映できる場合は、現在のインメモリ文書から印刷してください。

インメモリ状態を直接印刷できない実装方式を採る場合は、印刷開始前に保存が必要であることを確認し、ユーザーの明示的な選択なしに自動保存しないでください。

印刷処理のために別のPDFファイルを生成しないでください。

## 10．サイドバーをアイコン中心にする

ツールバーの`Sidebar`文字ボタンをアイコンへ置き換えてください。

サイドバー内の「Outline」「Thumbnails」も、日本語化した長い文字タブを常時並べるのではなく、目次とサムネイルを表すアイコンで切り替えられるようにしてください。

ホバー時に次を表示してください。

- `目次`
- `サムネイル`

サイドバー本文の状態表示やエラーは日本語にしてください。

PDFに目次がない場合は、簡潔に「目次はありません」と表示してください。

## 11．下部ステータス表示をデバッグ専用にする

現在の下部パネルにある性能・内部状態表示は、通常ビルドから除外してください。

対象例：

- PDFオープン時間
- 描画時間
- テキスト抽出時間
- 物理メモリ使用量
- GPUタイル数とキャッシュ容量
- 保存方式
- Highlight数
- 選択テキスト全文
- 内部状態を説明する英語メッセージ

### 11.1 デバッグビルド

`debug_assertions`などを使用し、デバッグビルドでだけ表示できる折り畳み式パネルへ移してください。

デバッグパネルは初期状態で閉じてください。

通常操作に必要な領域を常時占有しないでください。

### 11.2 通常のエラー表示

通常ビルドでも、ユーザーが対処すべきエラーは隠さないでください。

下部デバッグパネルの代わりに、次のいずれかで短く表示してください。

- ツールバー直下の一時的なエラーバナー
- 警告アイコンとツールチップ
- 操作を続行できない場合のモーダル

性能測定値とユーザー向けエラーを同じ表示経路へ混在させないでください。

## 12．選択テキストの下部表示を削除する

次の表示を削除してください。

- `Logical selection / Ctrl+C`
- 選択中テキストの全文
- 未選択時のMuPDF Quad説明

文字選択機能と`Ctrl+C`によるコピーは維持してください。

選択テキストをコピーした際に、下部パネルへ全文を表示しないでください。

必要なら、短時間の「コピーしました」という通知だけを表示してください。

## 13．ショートカットを整理する

最低限、次を維持または追加してください。

| 操作 | ショートカット |
|---|---|
| PDFを開く | `Ctrl+O` |
| 印刷 | `Ctrl+P` |
| 保存 | `Ctrl+S` |
| 検索欄へフォーカス | `Ctrl+F` |

| 元に戻す | `Ctrl+Z` |
| 次のタブ | `Ctrl+Tab` |

テキスト入力欄にフォーカスがある場合は、文字入力と編集操作を優先してください。

検索欄で`H`を入力した際にハイライトが作成されない既存対策を維持してください。

ページ番号欄や検索欄で`Ctrl+Z`を押した場合は、可能ならTextEdit自身の編集Undoを優先してください。

PDF編集のUndoは、入力欄が編集対象でない場合に実行してください。

- ページ全体
- 連続表示
- 単一ページ
- ハイライト
- 元に戻す
- 検索
- コピーしました
- 目次はありません
- サムネイルを読み込めませんでした

内部のoperation名、ログ識別子、エラー分類まで無理に翻訳する必要はありません。

ユーザーへ表示する最終メッセージだけ、原因と操作が分かる日本語へ変換してください。

## 15．実装順序

次の順序で実装してください。

1. 現状調査と変更箇所の特定
2. 20タブ制限の撤廃
3. 日本語フォント登録
4. メニューバーとツールバーの再構成
5. ページ番号入力
6. 検索欄の常設
7. Single Page表示のスクロール修正
8. デバッグパネルと選択テキスト表示の整理
9. 汎用編集履歴とUndo
10. 印刷機能
11. 回帰テストと手動確認

Undoと印刷はPDF本体またはOS APIへ触れるため、外観変更と混ぜて原因を追いにくくしないでください。

作業途中で問題が発生した場合は、未完の機能を有効なUIとして残さないでください。

## 16．検証

### 16.1 自動検証

少なくとも次を実行してください。

```text
cargo fmt --check
cargo check
cargo test
```

プロジェクトに既存のClippy運用がある場合は、既存設定に従って実行してください。

依存関係を変更した場合は、lockfile差分が必要な変更だけであることを確認してください。

### 16.2 タブ管理

- 21件目のPDFが拒否されない。
- 50件以上のPDFを開いても、上限エラーを出さない。
- 同じPDFを再度開くと既存タブへ移動する。
- 多数タブの状態でタブ切替と終了確認が動作する。
- 未保存タブが休止されない。
- セッション復元が20件で打ち切られない。

大量タブ試験には、小さな検証用PDFを使用してください。

リポジトリへ大量の生成PDFを残さないでください。

### 16.3 日本語

- 日本語ファイル名のPDFを開ける。
- タブに日本語ファイル名を表示できる。
- 日本語の目次を表示できる。
- 日本語検索文字列をIMEで入力できる。
- 日本語UIが豆腐文字や欠落表示にならない。
- Windowsと、既存CIまたは開発環境で利用しているLinuxの双方でビルドを確認する。

### 16.4 ページ移動

- ページ番号を直接入力して移動できる。
- 不正な値でページが変わらない。
- 入力中の値が自動更新で消えない。
- タブごとに入力状態が混ざらない。
- 前後ボタン、PageUp／PageDown、ページ入力が同じ移動処理を使用する。

### 16.5 Single Page表示

- ページが画面より大きい場合はページ内をスクロールできる。
- 下端から次ページへ移動できる。
- 上端から前ページへ移動できる。
- ページが画面内に収まる場合もホイールで前後移動できる。
- 1回のホイールジェスチャーで複数ページを飛ばさない。
- `Ctrl+ホイール`のズームが維持される。
- 先頭と最終ページの境界を越えない。

### 16.6 検索

- 検索欄が常時表示される。
- `Ctrl+F`で検索欄へフォーカスできる。
- EnterとShift+Enterで前後移動できる。
- Escapeで検索欄自体が消えない。
- 日本語検索が動作する。
- タブ切替後もタブごとの検索状態が混ざらない。

### 16.7 Undo

- ハイライト作成後に`Ctrl+Z`で取り消せる。
- 連続して複数回取り消せる。
- 既存のPDF注釈を削除しない。
- Undo後に表示、サムネイル、検索結果が更新される。
- Undo後のdirty状態が正しい。
- Undo履歴がタブ間で混ざらない。
- Undo不能時にボタンとメニューが無効になる。
- 検索欄やページ欄の文字編集Undoを奪わない。

### 16.8 印刷

- 印刷ボタン、メニュー、`Ctrl+P`が同じ処理を呼ぶ。
- 印刷ダイアログをキャンセルしても状態が壊れない。
- 指定ページ範囲を印刷できる。
- ページの縦横比が維持される。
- 複数ページ印刷でメモリがページ数に比例して増え続けない。
- 保存中は印刷を開始できない。
- Linuxビルドを壊さない。
- 印刷のために別PDFを生成しない。

### 16.9 リリースUI

リリースビルドで次を確認してください。

- 下部デバッグパネルが表示されない。
- 選択テキスト全文が表示されない。
- Saveボタンが存在しない。
- `Ctrl+S`などのショートカット文字列が常時表示されない。
- 検索欄は表示される。
- ユーザーが対処すべきエラーは確認できる。

## 17．完了条件

次をすべて満たした時点で完了としてください。

1. 20タブ上限がコード、UI、テストから除去されている。
2. 日本語UI、日本語ファイル名、日本語検索が正常に表示・入力できる。
3. メニューバーとSumatraPDF型の簡潔なツールバーが実装されている。
4. 開く、印刷、ページ直接入力、前後ページ移動が動作する。
5. Single Page表示でホイールスクロールとページ遷移が動作する。
6. 検索欄が常時表示される。
7. Undoが汎用編集履歴として実装され、現時点のハイライトを安全に取り消せる。
8. Saveボタンと常時表示が削除され、`Ctrl+S`は維持されている。
9. 下部の内部情報はデバッグビルドに限定されている。
10. 選択テキスト全文の下部表示が削除されている。
11. 外部PDFビューアで既存PDFと保存後の注釈を引き続き開ける。
12. 自動テストと必要な手動確認の結果が記録されている。
