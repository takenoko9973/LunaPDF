# Codex向け LunaPDF 注釈UI・カーソル・コピー操作 差分修正指示書

## 1．目的

直前の注釈UIおよびカーソル修正後に、実機で残っている表示・入力上の問題を修正してください。

本書は既存実装を置き換える全面改修ではありません。作業開始時点の最新`main`を基準に、今回確認された差分だけを修正してください。

対象は次の6点です。

1. 注釈一覧の内容を行の上下中央へ揃える。
2. 注釈一覧の文字選択を無効化し、文字上でも行操作を確実に受け付ける。
3. ツールバーとタブの文字を上下中央へ揃える。
4. 注釈色選択を同一ポップオーバー内へ統合し、クリック範囲を明確にする。
5. PDFの文字以外の領域で十字状カーソルになる問題を解消する。
6. PDF本文選択時の`Ctrl+C`を、「編集」→「コピー」と同じ処理へ接続する。

## 2．対象リポジトリ

- リポジトリ：`takenoko9973/LunaPDF`
- 対象ブランチ：作業開始時点の最新`main`
- 主な確認候補：
  - `src/app.rs`
  - `src/ui/sidebar.rs`
  - `src/ui/annotation_editor.rs`
  - `src/ui/viewport.rs`
  - `src/ui/icons.rs`
  - 入力イベント、タブ描画、クリップボード処理に関係するコードとテスト

上記は調査候補です。責務が別ファイルへ移動している場合は、最新構造を優先してください。

作業開始時に次を確認してください。

- 最新`main`のコミット。
- 未コミット差分の有無。
- `AGENTS.md`および現行の作業規約。
- 直前の注釈UI、ツールバー、カーソル修正内容。
- 既存のテストと検証記録。

## 3．変更範囲の制約

- 本書に記載していない機能を追加しないでください。
- ハイライトのQuad統合、PDF保存、Undo、注釈索引の既存仕様を変更しないでください。
- 依存関係を追加または更新しないでください。
- 類似する状態型、イベント型、UI部品を不用意に増やさないでください。
- 既存の型を無理に巨大化しないでください。
- 固定Yオフセットによる見た目だけの補正を避け、親レイアウトまたは描画基準を修正してください。
- 原因を確認せず、別の入力やカーソルへ置き換えて問題を隠さないでください。
- commit、push、PR作成は行わないでください。

# 4．注釈一覧を行の上下中央へ揃える

## 4.1 現象

注釈一覧の色スウォッチ、ページ番号、コメントが、確保された行領域の上側へ寄って見えます。

## 4.2 必須修正

各注釈行の内容を、行矩形の上下中央へ揃えてください。

次を満たしてください。

- 色スウォッチ、ページ番号、コメントの見かけの中心線を揃える。
- 行高を維持したまま、内容だけを中央へ配置する。
- 上余白や個別要素のY座標へ固定値を加える補正を行わない。
- DPI倍率が変わっても中央位置が崩れない。
- 文字のフォントメトリクスを考慮し、矩形の左上を基準に配置しない。

実装方法は最新コードに合わせて選定してください。

候補は次のとおりです。

- 行矩形全体を持つ子UIで、左から右かつ垂直中央のレイアウトを使用する。
- 行矩形へ直接描画し、文字を左中央基準で配置する。

直接描画する場合も、テキスト省略、クリップ範囲、テーマ色、DPIを既存UIと整合させてください。

## 4.3 受入条件

- 1行だけの場合も複数行の場合も、各行の内容が上下中央に見える。
- 色スウォッチと文字の上下位置が揃う。
- 日本語と半角英数字が混在しても、不自然な上下ずれを増やさない。
- 行高、項目間隔、一覧のスクロール挙動を壊さない。

# 5．注釈一覧の文字選択とクリック競合を解消する

## 5.1 現象

注釈一覧の文字上へカーソルを置くと、通常のリスト項目ではなく文字選択可能な表示になります。

また、文字要素が行側のクリック判定を奪う可能性があります。

## 5.2 必須修正

各注釈行を、一つの操作対象として扱ってください。

- ページ番号とコメントを選択不可にする。
- 子要素へ独立したクリック判定を持たせない。
- 行全体のResponseだけで、単クリック、ダブルクリック、右クリックを処理する。
- 色スウォッチ上、文字上、文字間、右側余白で同じ操作になるようにする。
- 文字上でもポインティングカーソルを維持する。
- ドラッグしても注釈一覧の文字選択を開始しない。
- 子要素と親要素でクリック処理を二重実行しない。

既存UI基盤で選択不可ラベルを使用できる場合は、それを使って構いません。ただし、文字上で行のクリック判定が失われないことを確認してください。

選択不可ラベルでも入力競合が残る場合は、行のResponseを先に確保し、色スウォッチと文字をPainterで描画してください。

## 5.3 維持する操作

- 単クリック：対象ページへ移動する。
- ダブルクリック：対象ページへ移動し、注釈編集を開く。
- 右クリック：既存の編集・削除メニューを開く。
- ホバー：行全体へフィードバックを表示する。
- 選択中の項目を常時強調する機能は追加しない。

## 5.4 受入条件

- 文字上でIビームまたは文字選択カーソルにならない。
- 文字をクリックしても対象ページへ移動できる。
- 文字をダブルクリックしても注釈編集を開ける。
- 文字上の右クリックでも既存メニューを開ける。
- 行の空白部分でも同じ操作ができる。
- 一つの操作が二重実行されない。

# 6．ツールバーとタブの文字を上下中央へ揃える

## 6.1 現象

ツールバーのラベルおよびタブタイトルが、各領域の上下中央からずれて見えます。

## 6.2 ツールバー

現在のツールバー高さと各コントロール高さを確認し、固定高の一行内で次を垂直中央へ揃えてください。

- アイコンボタン。
- 「ページ:」。
- ページ番号入力欄。
- 総ページ数。
- ズーム倍率。
- 検索欄。
- 検索件数。
- その他の通常ラベル。
- 区切り線。

次を守ってください。

- 個別のラベルだけにYオフセットを加えない。
- 親の水平レイアウトで中央揃えを明示する。
- TextEdit、ボタン、ラベルを同じ見かけの中心線へ揃える。
- ツールバーをSumatraPDF相当へ縮めた現在の高さを、不必要に元へ戻さない。
- クリック領域をさらに小さくしない。

## 6.3 タブ

タブタイトルと未保存マーカーを、タブ矩形またはタイトル領域の上下中央へ配置してください。

- 文字は左中央基準で描画する。
- 閉じるアイコンは、閉じる領域の中央を維持する。
- タイトルと閉じる領域を重ねない。
- 動的タブ幅、最小幅、最大幅を維持する。
- タブ高さを不必要に変更しない。
- 選択、ホバー、中クリックで閉じる操作を壊さない。

## 6.4 受入条件

- ツールバーの文字とアイコンが同じ中心線上に見える。
- タブタイトルがタブの上下中央に見える。
- 100%、125%、150%、200%相当のDPIで文字が切れない。
- ツールバーとタブの現在のコンパクトさを維持する。

# 7．注釈色選択UIを同一ポップオーバーへ統合する

## 7.1 現象

- 「その他の色」を選ぶと、色選択が別ウィンドウとして開きます。
- 現在色の色面だけが操作範囲に見え、文字や余白を押せることが分かりにくくなっています。
- プリセット色と最近使った色に、色名やカラーコードを表示する必要はありません。

## 7.2 編集パネル側のトリガー

注釈編集パネルの色欄は、色スウォッチだけでなく、横一行を一つのボタンとして扱ってください。

例：

```text
┌──────────────────────────┐
│  ■  色を選択           ▾ │
└──────────────────────────┘
```

次を満たしてください。

- 色スウォッチ、文字、余白、展開記号を含む一行全体をクリック可能にする。
- 通常時から操作範囲が分かる枠または背景を表示する。
- ホバー、押下、キーボードフォーカスを判別できる。
- 現在色はスウォッチで示す。
- 現在色の色名またはカラーコードを表示する必要はない。
- 無効状態では、既存の編集権限と処理中状態に従って操作不可にする。

## 7.3 プリセット色

プリセットは、色名を付けず、スウォッチだけを並べてください。

```text
プリセット
[■] [■] [■] [■] [■]
[■] [■] [■] [■] [■]
```

要求：

- 色名を表示しない。
- カラーコードを表示しない。
- 正方形の操作領域全体をクリック可能にする。
- 色面そのものより操作領域を少し大きくする。
- 選択中の色にはチェック、明確な外枠、または同等の表示を付ける。
- 色面の境界が白色や淡色でも識別できるようにする。
- ツールチップは必須としない。付ける場合も画面上の常時表示にはしない。

## 7.4 最近使った色

最近使った色も、色名とカラーコードを表示せず、スウォッチだけを並べてください。

```text
最近使った色
[■] [■] [■] [■] [■]
```

既存の履歴仕様を維持してください。

- 最大5色程度。
- 同一色を重複させない。
- 使用した色を先頭へ移動する。
- 既存のセッション保存方針に従う。
- 履歴が空の場合は、空の行を不自然に残さない。

## 7.5 「その他の色」

「その他の色…」は、文字を含む一行全体をクリック可能にしてください。

独立した`egui::Window`または別OSウィンドウとして開かず、現在の色選択ポップオーバー内へ展開してください。

例：

```text
┌──────────────────────────────┐
│ プリセット                   │
│ [■] [■] [■] [■] [■]        │
│ [■] [■] [■] [■] [■]        │
│                              │
│ 最近使った色                 │
│ [■] [■] [■] [■] [■]        │
│                              │
│ その他の色…                ∧ │
│ ┌──────────────────────────┐ │
│ │ カラーピッカー           │ │
│ │ RGB等の既存入力          │ │
│ │        [適用] [戻る]     │ │
│ └──────────────────────────┘ │
└──────────────────────────────┘
```

次を満たしてください。

- 「その他の色…」の行全体をクリック可能にする。
- 同一ポップオーバー内で折りたたみ・展開する。
- カラーピッカー操作中のドラッグで親ポップオーバーが閉じない。
- 「適用」までは注釈色を確定しない。
- 「戻る」またはキャンセルで、変更前の色を維持する。
- ポップオーバー外をクリックして閉じた場合、未適用のドラフトを破棄する。
- 適用したカスタム色を最近使った色へ反映する。
- 既存のカスタム色ドラフト状態を再利用できる場合は再利用する。
- この変更だけのために、不要な状態型を追加しない。

使用中のeguiでメニュー型Popupが内部のドラッグやクリックによって閉じる場合は、アンカー付きPopupとして開閉を明示管理するなど、操作を維持できる最小構成を選んでください。

## 7.6 受入条件

- 編集パネルの色欄一行をどこで押してもポップオーバーが開く。
- プリセットと最近使った色はスウォッチだけで表示される。
- 色名とカラーコードが常時表示されない。
- 各スウォッチの余白部分でも選択できる。
- 「その他の色」が同じポップオーバー内で展開される。
- カラーピッカーをドラッグ操作しても意図せず閉じない。
- 適用、キャンセル、外側クリックの結果が区別される。

# 8．PDF領域の十字状カーソルを解消する

## 8.1 現象

PDF表示領域では、文字上を除くほぼすべての場所で十字状または四方向移動状のカーソルになります。

以前の修正で、ページ内空白と灰色背景を開いた手、パン中を閉じた手にする設計が導入されていますが、Windows実機上の外観は改善していません。

## 8.2 期待するカーソル

| 対象または状態 | 期待するカーソル |
|---|---|
| PDF本文の文字 | Iビーム |
| リンク | 指差し |
| 注釈、画像、フォーム | 通常矢印 |
| ページ内の空白 | 開いたつかむ手 |
| ページ外の灰色背景 | 開いたつかむ手 |
| 左ドラッグによるパン中 | 閉じたつかむ手 |
| 中ボタン自動スクロール中 | 自動スクロール用カーソル |
| 自動スクロール終了後 | 直下の対象に応じたカーソルへ即時復帰 |

## 8.3 原因調査

まず、実機上で表示されているカーソルと、アプリが選択したカーソル列挙値を対応付けてください。

少なくとも次を同一フレームで確認してください。

- ポインター座標。
- ページ内、ページ外、文字、リンク、注釈などのヒット対象。
- 最終的なカーソル対象。
- `blank_pan`の有無とactive状態。
- 自動スクロール状態。
- 最終的に設定した`CursorIcon`。
- 同じフレーム内で別箇所がカーソルを上書きしていないか。
- フォーカス喪失、タブ切替、表示モード切替後に状態が残っていないか。

一時的なログまたはデバッグ表示を追加して構いませんが、通常ビルドへ不要な診断表示を残さないでください。

原因を次のように切り分けてください。

### `AllScroll`等が返っている場合

- 自動スクロール状態の開始条件と終了条件を確認する。
- 中ボタンを押していない状態で自動スクロールが成立していないか確認する。
- 状態解除後の同一フレームまたは次フレームでカーソルが再評価されるか確認する。
- タブ切替、フォーカス喪失、モード切替、文書revision変更後の解除経路を確認する。

### `Grab`が返っているのに十字状に見える場合

- 使用中のegui、eframe、winitとWindowsの標準カーソル対応を実機で確認する。
- 標準`Grab`が期待する開いた手として表示されないことを確認できた場合は、標準カーソルだけでは要件を満たせないと判断する。
- 別の標準カーソルへ置き換えて見た目を誤魔化さない。

### `Default`等が返っているのに十字状に見える場合

- カーソル設定の後勝ち上書きを調査する。
- ページ、背景、自動スクロール、オーバーレイ、グローバル入力処理に分散した設定を確認する。
- 最終設定箇所を一つに寄せる既存方針を維持する。

## 8.4 カスタムカーソルの条件

標準`Grab`と`Grabbing`がWindows実機で期待した開いた手と閉じた手にならないことを確認できた場合だけ、カスタムカーソルを検討してください。

導入する場合は次を満たしてください。

- 開いた手と閉じた手を別に用意する。
- Windows実機で外観とホットスポットを確認する。
- 100%、125%、150%、200%相当のDPIへ対応する。
- ライトテーマとダークテーマで識別できる。
- 配布物へ埋め込み、実行時の外部ファイルを必須にしない。
- SumatraPDFなど他製品の資産を無断で複製しない。
- ライセンスと配布条件を明示する。
- カーソル画像だけのために入力状態を二重管理しない。
- 他OSでは標準カーソルを維持できるよう、影響範囲を限定する。

使用中のライブラリまたはWindows APIで安全に実現できない場合は、推測で実装せず、調査結果と不足しているAPIを報告してください。

## 8.5 受入条件

- 中ボタンを一度も押していない起動直後から、ページ内空白と灰色背景が開いた手になる。
- 文字上はIビームになる。
- 注釈、画像、フォーム上は通常矢印になる。
- 左ドラッグの閾値超過後だけ閉じた手になる。
- 左ボタン解放後、開いた手へ戻る。
- 自動スクロール中だけ自動スクロール用カーソルになる。
- 自動スクロール停止直後に十字状カーソルが残らない。
- タブ切替、フォーカス喪失、表示モード切替後に状態が残らない。
- Windows実機でカーソル外観を確認する。確認できない場合は完了扱いにせず、未確認事項として報告する。

# 9．PDF本文選択時のCtrl+Cを修正する

## 9.1 確認済み事項

ユーザー実機では、「編集」→「コピー」は正常に機能します。

したがって、次は正常である可能性が高いと扱ってください。

- PDF本文の選択データ。
- 選択文字列の生成。
- クリップボードへの書き込み。
- 既存の`copy_selection`相当処理。

修正対象は、主としてキーボードショートカットの検出・優先順位・既存コピー処理への接続です。

ただし、最新コードで実際の経路を確認してから変更してください。

## 9.2 必須修正

PDF本文が選択されている状態で`Ctrl+C`を押した場合、「編集」→「コピー」と同じ既存処理を一度だけ実行してください。

- ショートカット側に文字列生成やクリップボード処理を複製しない。
- メニューとショートカットで同じ関数または同じアクション経路を使用する。
- キーリピートで不要な連続実行を行わない。
- PDF選択がない場合は何もしない。
- 古い選択文字列を再コピーしない。
- OS修飾キーの扱いは、使用中のeguiの標準的なショートカット表現へ合わせる。
- Windowsでは`Ctrl+C`が確実に動作することを確認する。

具体的なegui APIは、使用中のバージョンで確認してください。

候補として、ショートカット消費API、キーイベント、コピーイベントがありますが、調査前に方式を決め打ちしないでください。

## 9.3 テキスト入力欄との優先順位

次の優先順位を守ってください。

1. 注釈コメント欄にフォーカスがあり、欄内の文字が選択されている<br>
   → TextEdit自身のコピーを優先する。

2. 検索欄またはページ番号入力欄にフォーカスがあり、欄内の文字が選択されている<br>
   → その入力欄のコピーを優先する。

3. テキスト入力欄がコピー入力を所有しておらず、PDF本文の選択がある<br>
   → PDF本文をコピーする。

4. コピー対象がない<br>
   → 何もしない。

アプリ側が先に`Ctrl+C`を消費し、TextEditの標準コピーを壊さないでください。

単に「どこかがキーボード入力を要求している」だけでPDFコピーを常に無効化すると、メニューやPDF操作へフォーカスが残った場合に動作しない可能性があります。実際のフォーカス所有者とコピー対象を確認してください。

## 9.4 調査項目

- 現在`Ctrl+C`を検出するコードが存在するか。
- メニューのコピー要求がどこで既存コピー処理へ渡るか。
- `Ctrl+C`がキーイベントまたはコピーイベントとして届いているか。
- メニューバーの描画中だけショートカット判定していないか。
- TextEditがフォーカスを持つ場合にイベントがどう消費されるか。
- 同じ入力を複数箇所で処理していないか。
- Windowsと他OSで修飾キー抽象化が異ならないか。

## 9.5 受入条件

- PDF本文を選択し、`Ctrl+C`でコピーできる。
- 「編集」→「コピー」と`Ctrl+C`の結果が一致する。
- 日本語、半角英数字、複数行、逆方向選択で動作する。
- 注釈コメント欄の選択文字を`Ctrl+C`でコピーできる。
- 検索欄とページ番号入力欄の標準コピーを壊さない。
- 入力欄にフォーカスがある場合、PDF本文を誤ってコピーしない。
- PDF本文の選択がない場合は何もしない。
- 一回のキー操作でコピー処理が一回だけ実行される。

# 10．自動テスト

GUI外観そのものを直接テストできない場合も、判定ロジックを検証可能な単位へ分けてください。

少なくとも次を追加または更新してください。

## 10.1 注釈一覧

- 行の単クリックがページ移動へ対応する。
- ダブルクリックが編集へ対応する。
- 右クリックメニューの編集と削除を維持する。
- 子要素のクリック処理を必要としない。
- 読み取り専用注釈の操作制約を維持する。
- コメント省略処理を維持する。

上下中央や文字選択不可の外観は、可能な範囲でレイアウト矩形、Sense、Response所有関係を検証してください。

## 10.2 色選択

- プリセット選択。
- 最近使った色の重複排除。
- 最近使った色の最大件数。
- 選択色を先頭へ移動する。
- カスタム色の適用。
- カスタム色のキャンセル。
- 未適用ドラフトを閉じた場合の破棄。
- 無効状態で変更できない。
- セッション復元を維持する。

## 10.3 カーソル決定

- 文字は`Text`相当。
- リンクは`PointingHand`相当。
- 注釈、画像、フォームは通常矢印相当。
- ページ内空白と灰色背景は開いた手相当。
- パン成立中は閉じた手相当。
- 自動スクロール中だけ自動スクロール用カーソル。
- 自動スクロール停止後に直下の対象へ戻る。
- フォーカス喪失、タブ切替、モード切替で操作状態を解除する。
- 入力除外矩形上でPDF側がカーソルを上書きしない。

カスタムカーソルを導入する場合は、カーソル種別の決定とOS資産への変換を分離してください。

## 10.4 Ctrl+C

ショートカット判定を純粋関数または検証可能なアクション決定へ分離できる場合は、次をテストしてください。

- PDF選択あり、TextEditフォーカスなしでPDFコピー。
- PDF選択なしでは何もしない。
- 注釈コメント欄のコピーを優先する。
- 検索欄のコピーを優先する。
- ページ番号欄のコピーを優先する。
- 一つの入力でコピーアクションを一回だけ生成する。
- メニューとショートカットが同じコピー処理へ到達する。

# 11．手動受入確認

- 適用とキャンセルが区別される。

## 11.4 カーソル

起動直後、中ボタン未使用の状態から確認してください。

- 文字上：Iビーム。
- ページ内空白：開いた手。
- 灰色背景：開いた手。
- 注釈、画像、フォーム：通常矢印。
- 左ドラッグ中：閉じた手。
- 左ボタン解放後：開いた手。
- 自動スクロール中：自動スクロール用カーソル。
- 停止後：十字状カーソルが残らない。
- タブ切替、表示モード切替、フォーカス復帰後：状態が残らない。

実際のカーソル外観を確認できていない場合は、「コード上の列挙値が正しい」だけで完了扱いにしないでください。

## 11.5 コピー

- PDF本文を選択し、`Ctrl+C`でメモ帳などへ貼り付ける。
- 同じ選択を「編集」→「コピー」でもコピーし、結果を比較する。
- 日本語、英数字、複数行、逆方向選択を確認する。
- コメント欄、検索欄、ページ番号欄の選択文字を`Ctrl+C`でコピーする。
- 入力欄にフォーカスがある場合、PDF本文がコピーされないことを確認する。

# 16．作業報告

## 再現

- 使用したPDFまたはテスト条件。

- 操作手順。
- Windows実機で確認した外観。

## 原因

- 問題を発生させたファイルと関数。
- レイアウトが上へ寄った理由。
- 文字要素が行入力を奪った理由。
- 色選択が別ウィンドウになっていた構造。
- 十字状カーソルとして表示された実際の`CursorIcon`。
- カーソル状態または上書きの最初の不整合点。
- `Ctrl+C`が既存コピー処理へ到達しなかった理由。
- 原因確認に使用したログ、状態値、失敗テスト。

## 修正

- 変更したファイル。
- 各ファイルの変更理由。
- 行の中央揃え方法。
- 行入力を一つのResponseへ集約した方法。
- 色選択ポップオーバーの開閉とドラフト管理。
- 標準またはカスタムカーソルの採用理由。
- `Ctrl+C`とメニューコピーの共通経路。

## 検証

- 追加または更新したテスト。
- 実行したコマンドと結果。
- Windows実機の確認結果。
- DPI別の結果。

- 再現できなかった条件。
- 確認できなかったDPIまたは入力機器。
- 確認できなかったOS。
- カーソル外観の未確認事項。
- 手動確認できなかったショートカット競合。
- 残る既知の制約。

推測した原因を確認済みの事実として記載しないでください。
