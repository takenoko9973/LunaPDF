`docs/tasks/ui-improvement/lunapdf_codex_ui_improvement_instructions.md`
を置き換えるものではありません。実装済み機能を維持したまま、今回確認された問題と追加要求だけを対象にしてください。

## 1．日本語と半角英数字の表示位置を統一する

### 現象

同じラベルまたはツールチップ内で、日本語と半角英数字のベースライン、上下位置、文字高が揃っていません。

例：

```text
選択範囲をハイライト (H)
```

日本語部分と`(H)`の位置が異なって見えます。

### 原因として確認すべき点

現在のCJKフォント登録は、日本語フォントを低優先度のフォールバックとして追加し、半角英数字をegui既定フォント、日本語をCJKフォントで描画する構成です。

同一文字列内で異なるフォントのメトリクスが混在するため、ベースラインや見かけの高さが一致しない可能性があります。

### 必須修正

ユーザー向けの通常UIでは、日本語と半角英数字を同一のUIフォントファミリーで描画してください。

次のいずれかの方法を採用してください。

1. 選択したCJK対応フォントを、通常UIの`Proportional`フォントで最優先にする。
2. LunaPDF専用のUIフォントファミリーを定義し、メニュー、ラベル、ツールチップ、入力欄へ一貫して適用する。

CJKフォントはLatinグリフも持つものを使用し、同一ラベル内でフォントが切り替わらないようにしてください。

### 禁止事項

- 半角英数字を全角へ置換して問題を隠さない。
- ショートカット表記を`（Ｈ）`、`Ｃｔｒｌ`のような全角文字へ変換しない。
- PDF本文のフォント処理を変更しない。
- フォントファイルをリポジトリへ追加しない。

### 補足

`Monospace`まで一律にCJKフォントへ変更する必要はありません。

通常UIの混在文字列に使用するフォントを統一することが中心です。

フォント変更後も、検索欄とページ番号欄で日本語IMEおよびASCII入力が正常に動作することを確認してください。

## 2．アイコンの重なりと形状崩れを修正する

### 現象

一部のアイコンで、構成要素が互いに重なり、意図した形状に見えません。

特にUndoアイコンは、左向き矢印と円が重なって潰れて見えます。

### 必須修正

`src/ui/icons.rs`の全アイコンを見直し、次を満たしてください。

- 各アイコンはボタン内の共通した安全領域へ収める。
- 線端、矢印、円弧、枠線が意図せず交差しない。
- 隣のボタン領域へ描画しない。
- 選択状態、無効状態、ホバー状態でも形が崩れない。
- 100%、125%、150%、200%の表示倍率で判別可能にする。

Undoアイコンは、円全体と直線矢印を重ねる方式をやめ、一般的な「左向き矢印付きの円弧」として描画してください。

例：

- 右側から上側を回って左へ戻る円弧。
- 円弧の始点に左向きの矢印。
- 円弧と矢印の軸を二重に描かない。

### 描画境界

アイコン描画には明示的なクリップ領域を設定してください。

アイコン用矩形から一定の内側余白を取り、ストローク幅を含めても領域外へ出ないようにしてください。

### ツールバーの折り返し

現在のツールバーが折り返し可能なレイアウトの場合、狭い幅でボタン群が不自然に分断される可能性があります。

ツールバー全体は原則として折り返さないでください。

推奨：

- 通常の横一列レイアウト。
- 幅不足時は横スクロールまたは検索欄の可変縮小を使用する。
- 機能グループの途中で改行しない。

## 3．サイドバーボタンをツールバーの一番左へ移動する

ツールバーの並び順を次に変更してください。

```text
[サイドバー] [開く] [印刷] | ページ操作 | 表示操作 | 編集操作 | 検索
```

サイドバーボタンを、PDFを開くボタンより左へ配置してください。

PDFが開かれていない場合も位置は変えないでください。

サイドバーを利用できない状態では、ボタン位置を消すのではなく無効状態にしてください。これにより、PDFの有無でツールバー全体が左右へずれないようにします。

## 4．単ページ表示のホイール操作を修正する

### 現象

単ページ表示で、マウスホイールを1段動かしても1ページ遷移しない場合があります。

連続した小さい入力が蓄積されない、またはページ内スクロールに消費された後に蓄積状態が解除されている可能性があります。

### 現在の実装で確認すべき点

現在の処理には、次の性質があります。

- `smooth_scroll_delta`を使用している。
- 固定値の閾値へ到達するまでページ遷移しない。
- 一度遷移するとラッチし、入力deltaがゼロになるまで解除しない。
- ページ内スクロールとページ遷移の判定が同じdeltaを参照する。
- `ScrollArea`が入力を処理した後でも、グローバルなスクロールdeltaを参照している。

この構造では、ホイール1ノッチ、慣性付きホイール、高精度トラックパッドで挙動が一致しません。

### 4.1 ページ全体が画面内に収まる場合

縦方向の実質的なスクロール可能量がない場合は、通常のマウスホイール1ノッチで必ず1ページだけ遷移してください。

- 下方向1ノッチ：次ページ。
- 上方向1ノッチ：前ページ。
- 1ノッチで2ページ以上移動しない。
- 連続して2ノッチ入力した場合は2ページ移動できる。
- 先頭・最終ページを越えない。

この場合、固定値`32.0`などの論理ピクセル閾値へ単純に依存しないでください。

離散ホイール入力は、入力イベント単位またはホイール単位を考慮して判定してください。

### 4.2 ページが画面より大きい場合

- ページ端に達するまではページ内を通常スクロールする。
- 下端に達した後の追加の下方向入力で次ページへ移動する。
- 上端に達した後の追加の上方向入力で前ページへ移動する。
- 次ページへ移動した場合は上端を表示する。
- 前ページへ移動した場合は下端を表示する。

`PAGE_GAP`、丸め誤差、1ピクセル未満の余剰によって「端ではない」と判定され続けないよう、妥当な許容値を設けてください。

### 4.3 トラックパッドと連続入力

高精度トラックパッドでは、小さいdeltaを同一ジェスチャーとして蓄積してください。

一度ページ遷移した後は、同じ慣性ジェスチャーで複数ページを飛ばさないようにします。

ただし、ラッチ解除を「deltaが厳密にゼロのフレームが来ること」だけに依存させないでください。

次のいずれかを使用してください。

- 入力イベントの終了。
- 最終入力時刻からの短いアイドル時間。
- 方向反転。
- 新しい離散ホイールイベント。

### 4.4 入力の区別

- `Ctrl+ホイール`はズームとして処理する。
- 横方向入力は横スクロールとして処理する。
- ツールバー、検索欄、ページ番号欄、サイドバー上のホイールをPDFページ遷移に使わない。
- PDF中央表示領域にポインターがある場合だけ対象とする。

### 4.5 共通ページ移動処理

ホイール、PageUp／PageDown、ツールバー矢印、ページ番号入力で、ページ変更後の状態更新を可能な限り共通化してください。

ただし、ホイールによる前後移動では、上端／下端の復元位置を維持してください。

## 5．ページ遷移時のレンダリング待ちを短縮する

### 現象

単ページ表示で前後ページへ移動した際、ページが表示されるまで待ち時間があります。

### 原因として確認すべき点

現在の単ページ表示は、原則として現在ページのタイルだけを要求しています。

ページ変更時に描画世代を更新し、進行中のタイル要求を無効化しています。

ページ番号だけが変わり、ズーム、DPI、PDFリビジョンが変わっていない場合でも、全体的な描画無効化が行われています。

### 必須修正

ページ変更だけでは、ズームやDPI用の描画世代を更新しないでください。

描画世代を更新する条件は、少なくとも次に限定してください。

- ズーム倍率が変わった。
- 表示DPIが変わった。
- PDF内容のリビジョンが変わった。
- 表示モード変更によりタイル座標条件が変わった。
- 回転など、タイル内容を変える状態が変わった。

現在ページの変更だけなら、次フレームで`wanted_tiles`を切り替え、不要な要求だけを取り消してください。

既にキャッシュ済みの遷移先ページを即座に再利用できるようにしてください。

### 5.1 隣接ページの先読み

単ページ表示では、現在ページの可視タイルを最優先で要求した後、次を低優先度で先読みしてください。

- 次ページの上端側。
- 前ページの下端側。

ページ全体表示でページが画面内に収まる場合は、隣接ページの全表示範囲を先読みして構いません。

拡大表示の場合は、遷移直後に見える範囲だけを先読みし、ページ全体を無条件にラスタライズしないでください。

先読みは既存のGPUキャッシュ上限を尊重してください。

### 5.2 優先順位

順序は次としてください。

1. 現在ページの可視範囲。
2. 現在ページの直近スクロール範囲。
3. 次ページの遷移開始位置。
4. 前ページの遷移開始位置。
5. その他の低優先度処理。

検索、サムネイル、テキスト抽出が現在ページの可視タイルを長時間阻害しないようにしてください。

## 6．拡大縮小時のレンダリング待ちを短縮する

### 現象

ズーム操作のたびに、既存表示が消え、新しい倍率のタイルが完成するまで待たされます。

### 原因として確認すべき点

タイルキャッシュキーはズーム倍率のビット列を含み、倍率が少し変わるだけでも別タイルとして扱われます。

また、ズーム変更時に進行中要求を無効化し、現在倍率と完全一致するタイルだけを描画しているため、再描画中の代替表示がありません。

### 必須修正

新しい倍率のタイルを生成している間も、直前の有効なタイルを拡大縮小して暫定表示してください。

暫定表示に使えるタイルは、次をすべて満たすものに限定してください。

- 同じ文書。
- 同じページ。
- 同じPDFリビジョン。
- 同じ回転。
- 現在のDPIと互換性がある、または安全に論理座標へ変換できる。
- キャッシュに実在する。

現在倍率に最も近いタイルを選び、正確な倍率のタイルが到着した領域から順次置き換えてください。

新しいタイルが完成するまで白紙や`Rendering page...`だけを表示しないでください。

### 6.1 ズーム入力の統合

連続ホイールズーム中に、途中の全倍率を順番に完全レンダリングしないでください。

短時間に連続したズーム入力は統合し、最新倍率を優先してください。

実装方法は次のいずれかとします。

- 短いデバウンス後に最終倍率を高精細レンダリングする。
- 可視中心タイルだけ即時要求し、残りは入力停止後に要求する。
- 進行中要求を最新倍率へ置き換える。

操作中は暫定拡大表示を維持してください。

固定の待ち時間を長くし、操作反応を悪化させないでください。

### 6.2 キャッシュの扱い

ズーム変更時に、旧倍率のタイルを直ちに全削除しないでください。

GPUキャッシュ上限へ達した場合は、既存のLRU方針で古い倍率を削除してください。

PDF内容変更後の古いリビジョンタイルは、暫定表示へ使用しないでください。

## 7．ブラウザ型の中ボタン自動スクロールを追加する

### 要求

PDF表示領域でマウスホイールを押し込むと、ブラウザのオートスクロールに近い操作を開始できるようにしてください。

単なる「中ボタンを押している間だけドラッグ移動」ではなく、クリック後に移動量で速度を制御するブラウザ型を基本とします。

### 7.1 開始

PDF中央表示領域で中ボタンをクリックした場合だけ開始してください。

次の場所では開始しないでください。

- メニューバー。
- タブバー。
- ツールバー。
- 検索欄。
- ページ番号欄。
- サイドバー。
- モーダルダイアログ。

開始地点をアンカーとして保存し、アンカー位置に小さいオートスクロールマーカーを表示してください。

カーソルは可能なら全方向スクロールを示すものへ変更してください。

### 7.2 移動

アンカーから現在のポインターまでの距離と方向でスクロール速度を決めてください。

- 中央付近にデッドゾーンを設ける。
- 距離が大きいほど速くする。
- 最大速度を制限する。
- 上下左右へ移動できる。
- フレームレート差で速度が大きく変わらないよう、経過時間を考慮する。

### 7.3 終了

次の操作で終了してください。

- 中ボタンを再度クリック。
- 左ボタンまたは右ボタンをクリック。
- Escape。
- ウィンドウがフォーカスを失う。
- タブを切り替える。
- PDFを閉じる。
- モーダルダイアログを開く。

### 7.4 表示モード別の挙動

#### 連続表示

既存の縦横スクロール範囲内を連続移動してください。

#### 単ページ表示

ページ内を移動し、上下端へ到達した状態で外向きの速度が継続した場合は前後ページへ移動してください。

- 下端から次ページへ移動した場合は上端から続行する。
- 上端から前ページへ移動した場合は下端から続行する。
- 1フレームで複数ページを飛ばさない。
- ページ切替後に短いクールダウンまたは距離条件を設ける。

### 7.5 競合防止

- 左ボタンドラッグによるテキスト選択を変更しない。
- 中ボタン操作中にテキスト選択を開始しない。
- `Ctrl+ホイール`ズームへ影響しない。
- 通常ホイール操作へ影響しない。
- スクロール可能範囲外へオフセットを設定しない。

オートスクロール状態はタブ切替後に残さないでください。

## 8．性能計測を追加する

体感だけで修正完了としないでください。

デバッグビルドで、少なくとも次を測定できるようにしてください。

### 8.1 ページ遷移

- 入力受信から最初の有効タイル表示まで。
- 入力受信から可視範囲の全タイル完成まで。
- キャッシュヒットの有無。
- 先読みタイルの利用有無。

### 8.2 ズーム

- ズーム入力から暫定表示まで。
- ズーム入力停止から最初の正確な倍率タイルまで。
- 正確な可視範囲の完成まで。
- 途中倍率で破棄した要求数。

性能情報はデバッグパネルまたはログだけに表示し、リリースUIへ常時出さないでください。

## 9．検証

### 9.1 自動検証

```text
cargo fmt --check
cargo check
cargo test
cargo clippy --all-targets
cargo check --release
```

Windows固有コードへ変更がある場合は、Windows MSVC環境でも確認してください。

`libclang.dll`不足などで製品コードへ到達しなかった場合は、Windowsビルド成功として報告しないでください。

### 9.2 フォント

- `選択範囲をハイライト (H)`で日本語と`(H)`の上下位置が揃う。
- `PDFを開く (Ctrl+O)`で日本語と半角文字のベースラインが揃う。
- メニュー、ツールチップ、検索欄、エラー表示で同様に揃う。
- 100%、125%、150%、200%の表示倍率で確認する。
- 日本語IMEとASCII入力が動作する。

### 9.3 アイコン

- Undoアイコンが円弧と矢印として判別できる。
- HighlightアイコンとUndoアイコンが互いに重ならない。
- 全アイコンがボタン領域内に収まる。
- 狭いウィンドウでもツールバーが機能単位の途中で折り返されない。
- 無効状態と選択状態でも形状が崩れない。

### 9.4 単ページホイール

通常のノッチ式マウスで確認してください。

- ページ全体表示中、1ノッチで1ページ移動する。
- 2ノッチで2ページ移動できる。
- 1ノッチで複数ページ移動しない。
- 拡大中は端までページ内スクロールする。
- 端で追加1ノッチすると隣接ページへ移る。
- 前ページへ戻る場合は下端から表示される。
- 次ページへ進む場合は上端から表示される。

可能なら高精度ホイールまたはトラックパッドでも確認してください。

確認できない入力機器は未確認と報告してください。

### 9.5 ページ遷移性能

- 既に表示したページへ戻ると即座にキャッシュ表示される。
- 次ページの先読みが成功した場合、白紙待ちが発生しない。
- ページ変更だけで描画世代が不要に変わらない。
- 古いPDFリビジョンのタイルを表示しない。

### 9.6 ズーム性能

- ズーム中も直前画像の暫定表示が残る。
- 正確な倍率のタイルへ段階的に置き換わる。
- 連続ズームで途中倍率の要求が無制限に蓄積しない。
- ズーム入力停止後に最終倍率が鮮明になる。
- 検索ハイライトと文字選択位置が表示倍率に追従する。

### 9.7 中ボタン自動スクロール

- PDF領域内だけで開始する。
- クリック後、ポインター距離で速度が変わる。
- 上下左右へ移動する。
- 指定した終了操作ですべて停止する。
- タブ切替後に残らない。
- 単ページ表示で端から隣接ページへ移動できる。
- テキスト選択を壊さない。
