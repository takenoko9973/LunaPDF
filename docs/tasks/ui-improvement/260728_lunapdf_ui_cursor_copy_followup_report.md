## 原因

### 注釈一覧

`src/ui/sidebar.rs::show_highlights` は28ptの行Responseを先に確保した後、その矩形の上へ子UIを作り、スウォッチとLabelを通常レイアウトしていた。

- 子UIの内容は確保済み行矩形の上端から配置され、行高に対する上下中央を描画基準にしていなかった。
- Labelが独自Responseを持つため、文字上の入力と親行Responseが競合し、行全体を一つの操作対象として保証できなかった。

### ツールバーとタブ

ツールバーは、行の固定高を先に確保せずに子要素を順番に配置していた。後から24ptのTextEditやボタンで行高が広がっても、先に配置済みのラベルを新しい中心へ戻せない構造だった。

タブは最新 `main` ですでにタイトルgalleyと閉じるアイコンを各領域の中心へ配置していた。ソース上の追加修正理由は確認できなかった。

### 色選択

トリガーは28ptのスウォッチだけがResponseで、隣の色名表示はクリック対象外だった。また、カスタム色はポップオーバーを閉じて独立した `egui::Window` を開く構造だったため、同一ポップオーバー内で適用・取消・外側クリックを区別できなかった。

### カーソル

アプリのカーソル決定は期待どおりだったが、Windows側のwinit標準カーソル変換が `Grab` と `Grabbing` を同じ `IDC_SIZEALL` に割り当てていた。状態解除や上書きではなく、標準カーソルのOS変換が最初の不整合点だった。

### `Ctrl+C`

メニューの「コピー」は `PrototypeApp::copy_selection` を直接呼んで正常に既存経路へ到達する。一方、キーボード側は `consume_key(CTRL, C)` だけを調べていた。Windowsの `Ctrl+C` はその前段のegui-winitで `Event::Copy` に変換されるため、キーボード側の条件が成立しなかった。

## 修正

### `src/ui/sidebar.rs`

- 行矩形からスウォッチ矩形とテキスト矩形を計算し、双方の中心Yを行矩形の中心Yへ合わせた。
- フォントで生成したgalley高を使い、固定ベースライン補正を置かずに文字を上下中央へ描画した。
- スウォッチと文字をPainterで描き、単クリック、ダブルクリック、右クリック、ホバーを親行Responseだけへ集約した。
- Painter化後もページ番号とコメントを読み上げられるよう、同じ親行Responseへアクセシビリティ名を付けた。
- 既存の行高、コメント先頭48文字、省略、編集・削除権限を維持した。

### `src/app.rs`

- ツールバーのスクロール内容を既存の24ptへ固定してから `horizontal_centered` で配置し、ラベル、TextEdit、区切り、アイコンの中心線を共通化した。
- PDFカーソル設定を `ui::cursor::set_pdf_cursor` に集約し、既存のカーソル決定結果をWindows資産へ変換するだけにした。
- `Event::Copy` を処理し、PDF選択がある場合だけ既存の `copy_selection` を呼ぶようにした。文字列生成やクリップボード命令は複製していない。
- TextEditに実選択範囲がある場合は `Event::Copy` を残し、検索欄、ページ番号欄、注釈コメント欄の標準コピーを優先する。
- `Event::Copy` に押下Keyイベントが付かないため、最小のラッチを追加した。イベント順を維持し、対応するC、Insert、専用Copyキーの解放またはフォーカス喪失で解除して、キーリピート中のPDF再コピーを抑止する。

### `src/ui/annotation_editor.rs`

- 現在色のスウォッチ、固定ラベル、余白、展開記号を含む横一行を一つのButton Responseにした。
- 通常、ホバー、押下、フォーカス、無効状態の既存visualsを使って操作範囲を示した。
- プリセットと最近使った色は常時表示をスウォッチだけにし、28ptの操作領域内へ18ptの色面を描画した。
- 「その他の色…」を同じPopup内で展開し、既存の `custom_color_draft` を再利用した。
- 「適用」だけが注釈色と最近使った色を更新する。「戻る」、外側クリック、Escape、トリガーによる閉鎖、編集不可への遷移は未適用ドラフトだけを破棄する。
- 独立した `egui::Window` と常時表示の色名・カラーコードを削除した。

### `src/ui/cursor.rs`

- Windowsの `Grabbing` だけを、閉じた手のカスタムRGBAカーソルへ変換する小さな適応層を追加した。非パン時はカスタムカーソルを設定しない。
- 32、40、48、56、64pxをキャッシュし、100%、125%、150%、175%、200%相当の倍率から最も近いサイズを選ぶ。
- 黒い輪郭と白い塗りでライト・ダーク双方の背景から分離し、ホットスポットは手の中心へ置いた。
- 画像はLunaPDF用に新規作成した幾何から実行時に埋め込みRGBAを生成する。外部ファイルを追加せず、本パッケージの `AGPL-3.0-only` で配布する。
- `Default`、`Text`、`PointingHand`、`AllScroll` は標準処理を維持し、非Windowsも標準の `Grabbing` を使う。

### `src/ui/viewport.rs`

- アイドル時の選択可能な文字へ `Text`、リンクへ `PointingHand`、その他のPDF対象へ `Default` を返し、パン候補であることだけを理由に `Grab` を返さないようにした。
- パン候補の押下だけでは通常矢印を維持し、既存のドラッグ閾値を超えて `blank_pan_active` になった後だけ `Grabbing` を返す。
- パン中に文字上へ横切っても閉じた手を維持し、解放後は同じフレームの対象に応じたカーソルへ戻す。
- 自動スクロール中の `AllScroll` とリンク上の `PointingHand` は維持した。

### 文書

- 指示書を `docs/tasks/ui-improvement/` へ分類し、`docs/tasks/README.md` の索引を更新した。
- 本報告書を同じ分類フォルダへ追加した。
