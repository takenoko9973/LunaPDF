## 2. 再現・現状と原因

### 2.1 注釈色

- バックエンドの新規Highlight既定色は `#FFFF00` だったが、UIの黄色プリセットは `#FFEB3B` だった。
- 現在色と候補色を文字色へ使っていたため、黄色などの明色は背景とのコントラストが不足した。
- 任意色pickerは親メニュー内にあり、pickerの継続操作より先に親メニューが閉じ得る構造だった。実GUIでの失敗操作は今回の自動操作環境では再現完了していないが、編集バッファ以降の更新、dirty、worker、revision、保存、再読込経路は既存テストと追加テストで確認した。

### 2.2 注釈hoverと重複候補

- ページ上の注釈ヒット判定は既にQuad単位で安定IDを返していたが、hoverコメント表示へ利用していなかった。
- 重複候補の表示文字列は色名またはカラーコードを含み、色スウォッチを持っていなかった。

### 2.3 空白パンと選択解除

- 選択開始点は距離上限なしで最寄りglyphへ吸着できたため、文字から遠い余白もテキスト対象になり得た。
- ページ内空白とページ外灰色背景には、ドラッグ閾値後に2軸パンへ遷移する共通経路がなかった。
- 選択範囲外の単純左クリックを明示的な選択解除へ変換する経路がなかった。

### 2.4 中ボタン自動スクロール、タブ、アイコン

- 自動スクロール最大速度は `1,600 pt/s` で、単一ページ表示からも開始可能だった。
- タブ本体の中クリックを既存 `close_tab` へ渡す経路がなかった。
- アイコンは各列挙値が `../../assets/icons/...` を個別に指定していた。

### 2.5 ハイライト一覧

- 既存 `AnnotationPageSnapshot` はQuadとopacityを含み、表示ページ用キャッシュは不可視ページを破棄するため、文書全体の一覧キャッシュには適さなかった。
- `LoadAnnotations` は前景操作かつ表示ページ単位であり、文書全体走査へ流用すると表示処理と競合する構造だった。
- 注釈のxrefはrevision有効期間内だけ安定するため、保存・再読込時の全リセットと、通常編集時の変更ページ限定更新を分ける必要があった。

## 3. 変更

### 3.1 色UI、任意色、候補、hover

- 黄色プリセットを新規既定色と同じ `#FFFF00` へ変更した。既存PDFの `#FFEB3B` は読み取った値のまま保持し、ユーザーが新たに黄色を選んだ場合だけ `#FFFF00` を書き込む。
- 現在色と5色プリセットを境界線付きスウォッチで表示し、説明文字は通常のUI前景色にした。選択状態は色差だけでなくチェック表示でも示す。
- 任意RGB pickerを親メニューから、閉じない注釈編集オーバーレイへ移した。
- 重複候補はコメント先頭と安定IDを残し、色名とカラーコードを除去してスウォッチを追加した。
- コメントが空でない全重複注釈をPDF内順でhover表示する。選択ドラッグ、空白パン、自動スクロール、コンテキストメニュー、編集オーバーレイ、候補メニュー中は抑制する。

### 3.2 空白パン、クリック解除、非テキスト対象

- eguiの既存 `max_click_dist` を現在のzoomからページ座標へ変換し、選択開始点だけへ距離上限を導入した。開始後の端点は従来どおり最寄りglyphを使うため、行頭、行末、1文字、逆方向選択を維持する。
- MuPDF構造化テキストの画像block、解決済みlink、widgetを `non_text_targets` として保持し、その上から空白パンを開始しない。
- ページ内空白と中央表示領域の灰色背景は、閾値を超えた後だけGrabからGrabbingへ遷移し、ポインター移動と逆方向へ2軸スクロールする。スクロール範囲は既存ScrollAreaへクランプする。
- 選択範囲外の単純左クリックはselection generationを進めて解除する。空白パンは閲覧移動中の偶発的な選択消失を避けるため、既存選択を保持する。
- タブ、ツールバー、サイドバー、メニュー、検索欄、注釈オーバーレイなどは中央表示領域外または除外layerとして扱い、入力を奪わない。

### 3.3 自動スクロール、タブ中クリック、アイコン

- 最大速度だけを `4,800 pt/s` へ変更し、dead zoneと加速率は維持した。
- 単一ページ表示では開始せず、モード切替時に速度、端数、anchor、cursorを含む状態を破棄する。
- タブ中クリックは対象タブを先に選択せず、既存 `close_tab` へ渡す。dirty確認、保存・印刷制約、ワーカーとキャッシュ解放は既存経路を再利用する。
- 全14アイコンを `CARGO_MANIFEST_DIR` 基準の共通マクロでコンパイル時埋め込みし、公開キャッシュ識別子は `bytes://assets/icons/...` とした。ソース上のアイコン参照から `../` を除去した。

### 3.4 ハイライト索引と一覧

- `AnnotationSummary` を追加した。責務は安定ID、種別、コメント、色、編集・削除権限だけを持つ軽量な共通注釈表現であり、Quad、opacity、egui状態、進捗を持たない。
- `AnnotationSnapshot::summary` にgeometry付き表現からの変換を集約し、MuPDF列挙も共通 `annotation_summary` から表示ページsnapshotと索引summaryを構築する。
- `HighlightIndexRequest`、`HighlightIndexPage`、`HighlightIndexBatch` は、世代・revision・連続ページ範囲・ページごとの実測時間だけを運ぶworker契約とした。
- 一覧を初めて開いた時だけ走査を開始する。結果は文書タブの `BTreeMap` に保持し、サイドバーを閉じたり別タブへ切り替えたりしても破棄しない。
- 走査はworkerのbackground queueへ送り、可視描画、ページ移動用描画、テキストsnapshot、注釈編集・削除、Undo、保存、Shutdownより低い優先度にした。
- 一度に1バッチだけ要求し、受信済みページをすぐ一覧へ追加して `取得ページ数 / 総ページ数` を表示する。
- generationは要求前とMuPDF処理後の両方で確認する。キャンセルが非割込みMuPDFバッチ中に届いても、旧バッチの完成結果を `HighlightIndexReady` として送らない。
- 新規作成、コメント・色更新、削除、Undoは変更ページだけを1ページバッチで置換する。通常編集ごとの全再走査は行わない。
- 保存・再読込・ページ不明のrevision変更はxref有効期間が変わるため全リセットする。古いgeneration、revision、要求範囲、別タブの結果は適用しない。
- 一覧行はスウォッチ、ページ番号、最初の非空コメント行を最大48文字で表示する。全文はhoverへ保持し、全体が空白の場合だけ `コメントなし` とする。
- 永続選択行は持たない。単クリックはページ移動だけ、ダブルクリックと右クリック編集はページ移動後にsummaryから既存editorを開き、右クリック削除は既存削除要求へ渡す。編集・削除権限がない操作は無効化する。ページ内注釈位置への精密移動は今回追加していない。

### 3.5 型の代案

- 全ページ分の `AnnotationSnapshot` を保持する案は、一覧に不要なQuadを重複保持するため不採用とした。
- `SidebarHighlightItem` のような画面専用型は作らず、editorでも利用できる `AnnotationSummary` に限定した。
- 索引進捗、hover、popup、ページ移動要求をsummaryへ混在させず、ドメイン情報、タブ単位索引状態、UI操作を分離したため神型にはしていない。
- 索引専用workerや別データベースは追加せず、既存の文書所有workerとrevision直列化を再利用した。

### 4.1 測定環境と方法

- 測定対象: 実際のMuPDF `load_pdf_page` と `page.annotations()`。100、500、1,000ページ、各ページ0、1、10件のHighlightを生成した。
- 各条件を8、16、32ページバッチで走査し、summaryを全ページ分保持した。
- `first_batch_ms` は同期バックエンド要求開始から最初のバッチ返却、`first_item_ms` は最初のHighlightを含むバッチ内処理完了、`total_ms` は全走査時間である。
- `gap_us` はこの同期性能harness内で前バッチ処理終了から次呼出しまでの時間であり、UI・channel往復時間ではない。
- `max_batch_ms` は測定中の最長非割込みバッチ時間であり、実GUIの「キャンセル要求から停止まで」そのものではない。


### 4.3 バッチサイズ判断

- 8ページは、1,000ページ・10件/pageで最初の項目が0.112 ms、最長バッチが0.175 msだった。
- 同条件の16ページは0.192 msと0.355 ms、32ページは0.380 msと0.486 msだった。
- 1,000ページ・10件/pageの総時間は8ページが13.203 ms、16ページが12.096 ms、32ページが12.455 msで、8ページの総時間差は約1.1 msだった。
- 初回部分結果とキャンセル境界を優先し、総時間が同程度だった8ページを採用した。
- 観測RSS差分は0から1,740,800 bytesだった。allocator再利用で0となる条件が多いため、厳密な索引割当上限とは扱わない。

### 4.4 性能上の確認範囲

- 実MuPDFページ読込、注釈列挙、summary保持、初回バッチ、全走査、ページ平均・中央値・p95、harness内gap、RSS、最長バッチを測定した。
- worker schedulerの自動テストで、可視描画が背景索引より先に選ばれること、キャンセル済みgenerationがready結果を返さないことを確認した。
- 実GUIでのキャンセル要求から停止まで、索引中の可視ページ描画時間、ページ移動応答、注釈編集応答、タブ切替応答は計測していない。同期harnessの `gap` または `max batch` をこれらの実測値として扱わない。
