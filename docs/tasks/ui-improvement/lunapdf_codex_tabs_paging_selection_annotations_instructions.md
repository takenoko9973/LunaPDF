# Codex向け LunaPDF タブ・ページ操作・テキスト選択・注釈編集 改善指示書

## 目的

作業開始時点の最新`main`を基準に、次の不具合と追加要求を調査・実装してください。

1. タブの閉じるボタンの下側が薄く見える。
2. タブの閉じるボタンが右端から離れている。
3. ページ番号欄を3桁のページ番号を前提とした幅にする。
4. 「単一ページ表示」かつ「幅に合わせる」で、ホイールによるページ遷移ができない。
5. 単純な左クリックまたは微小な移動だけでテキスト範囲が選択される。
6. 選択表示が文字ごとのブロックに分断されている。
7. 選択範囲または注釈上の右クリックメニューを追加する。
8. ハイライト注釈のコメント、色、削除を編集できるようにする。
9. 他のPDFソフトで作成されたハイライトも編集対象にする。
10. 注釈編集UIを、PDF表示領域をリフローさせない右端固定オーバーレイとして実装する。

具体的なegui API、MuPDF API、型名、固定値は本書で決め打ちしません。最新コード、使用中の依存バージョン、利用可能なAPI、PDF仕様上の制約を確認し、要件を満たす最小かつ保守可能な実装を選定してください。

# 4．タブの閉じるボタン

## 4.1 現象

- Xの下側が上側より薄く見える。
- Xがタブ右端から離れている。

添付スクリーンショットと同じ条件で再現し、文字グリフ、フォントメトリクス、クリップ、描画位置、色、DPIのどこで差が生じるか確認してください。

## 4.2 必須仕様

- Xを構成する2本の斜線は、見かけの太さが均一である。
- 通常、ホバー、押下、選択、無効状態で形が崩れない。
- Xの見た目をタブ右側へ寄せる。
- クリック領域は十分な大きさを維持し、タブ右端側に置く。
- タイトルが閉じる領域へ重ならない。
- 最小タブ幅でも閉じる操作を維持する。
- Xの押下で背後のタブ選択を同時に起こさない。

文字グリフを継続するか、均一な線、既存資産、別の図形表現へ変更するかは固定しません。複数DPIで安定し、現行のアイコン方針と責務分離を壊さない方法を選んでください。

## 4.3 検証

- 100%、125%、150%、200%相当の表示倍率。
- 選択中・非選択・ホバー・無効状態。
- 最小幅のタブ。
- 長い日本語ファイル名。
- 1タブ、多数タブ、横スクロール発生後。

# 5．ページ番号欄を3桁前提にする

- 現在ページ入力欄は少なくとも`999`を余裕を持って表示・編集できる幅にする。
- 少なくとも次が欠けずに表示されること。

```text
[ 999 ] / 999
```

- 1桁・2桁でも不自然に位置が変わらない。
- 3桁で末尾がクリップされず、通常は入力欄内の横スクロールを必要としない。
- 4桁以上のPDFでも入力機能を使用不能にしない。
- 4桁以上への表示方式は現行レイアウトを確認して決めるが、切り捨て、入力拒否、誤遷移を行わない。
- ツールバーの高さや文字のY位置へ固定補正を追加しない。

1、9、10、99、100、999を表示・入力し、可能なら4桁以上のfixtureでも破綻しないことを確認してください。

# 6．単一ページ表示・幅合わせ時のホイール遷移

## 6.1 現象

「単一ページ表示」かつ「幅に合わせる」で、ホイールを操作しても隣接ページへ遷移できない。

既存の単一ページ用ホイール処理を全面的に作り直す前に、FitWidth時のページ寸法、ScrollAreaのcontent size、viewport size、開始・最大オフセット、端判定、イベント消費順序を確認してください。

## 6.2 必須挙動

ページが表示領域より縦に長い場合：

- 通常のホイールでページ内を上下にスクロールする。
- 下端へ到達した後、さらに下方向へ入力すると次ページへ移動する。
- 上端へ到達した後、さらに上方向へ入力すると前ページへ移動する。
- 端へ到達させる入力とページ遷移を同時に行わず、端に到達した後の追加入力で遷移する既存方針を維持する。

ページが縦方向に収まる場合：

- 下方向で次ページ、上方向で前ページへ移動する。

遷移後：

- 次ページは上端から表示する。
- 前ページは下端から表示する。
- 先頭・最終ページの境界を越えない。

## 6.3 入力の区別

- `Ctrl+ホイール`をページ遷移にしない。
- 横方向入力をページ遷移にしない。
- PDF中央領域にポインターがある場合だけ対象にする。
- タブ、メニュー、ツールバー、検索欄、ページ番号欄、左サイドバー、注釈編集オーバーレイ上のホイールをPDF遷移へ流さない。
- 1ノッチで複数ページを飛ばない。
- 高精度入力は小さいdeltaを適切に蓄積する。
- 一度遷移した後、同じ慣性ジェスチャーで連続遷移しない。

## 6.4 計測

- 表示・ズームモードと現在倍率。
- ページ論理寸法、viewport size、content size、ページ表示矩形。
- 開始・出力・最大スクロールオフセット。
- 上端・下端・収まり判定。
- raw wheel eventのunit、delta、phase、modifiers。
- pointer over view。
- 蓄積量、方向、ラッチ、最終入力時刻。
- page deltaと遷移後アンカー。

## 6.5 回帰テスト

- 単一ページ＋FitWidthの縦長ページでページ内スクロールできる。
- 下端・上端の追加入力で前後ページへ移る。
- 縦方向に収まるページは直接前後移動できる。
- FitPage、固定倍率を壊さない。
- Line／Page単位入力とPoint単位入力を分ける。
- `Ctrl+ホイール`、横方向入力、先頭・最終ページ境界。
- オーバーレイ上のホイールでPDFページが変わらない。

# 7．単純クリックとドラッグ選択を区別する

## 7.1 必須仕様

- 単純な左クリックだけでは新しい選択を作らない。
- 押下位置から十分な距離を移動した場合だけドラッグ選択を開始する。
- 閾値未満の手ぶれを選択として確定しない。
- 意図的なドラッグであれば、同一glyph内で終了しても1文字選択を許可する。
- 1文字選択の可否と、クリックのみの除外を別条件として扱う。
- 逆方向ドラッグでも同じ論理範囲を選ぶ。
- ページ端外へ少し出た場合のクランプを維持する。
- 右クリックで選択を開始しない。
- 注釈上のダブル左クリックをドラッグ選択として誤処理しない。

閾値は固定しません。現行eguiのドラッグ判定、DPI、過去のsynthetic drag検証の注意点を確認し、通常クリックを除外しつつ短い1文字ドラッグを妨げない値・方法を選んでください。

## 7.2 テスト

- 同一位置の押下・解放では選択しない。
- 閾値未満では選択しない。
- 閾値以上では選択する。
- 閾値以上で同一glyphなら1文字選択になる。
- 複数文字、複数行、逆方向。
- 右クリック、注釈ダブルクリックとの競合。

# 8．選択表示を行単位の連続領域へ統合する

## 8.1 必須仕様

- 同じ行で連続する選択文字を一つの連続した帯として表示する。
- 文字間の小さい隙間と空白文字も同じ行の選択領域として連続させる。
- 改行した場合は行ごとに別の帯とする。
- 複数行全体を一つの外接矩形で覆わない。
- 文字ごとの外枠線を表示しない。
- 半透明の塗りを基本とする。
- 行をまたいで誤結合しない。
- 縦書き、回転、傾斜などの幾何情報を無視して水平矩形へ固定しない。
- Typst PDFで選択範囲が過度に広がる問題を再発させない。

## 8.2 論理範囲との整合性

次の4つは同じglyph範囲を表す必要があります。

1. ドラッグ中のプレビュー。
2. ドラッグ確定後の表示。
3. コピー文字列。
4. ハイライト作成へ渡すQuad。

表示用に行単位へ結合しても、コピー順、両端包含、PDFへ保存する論理範囲を変えないでください。表示用geometryと注釈保存用Quadを同じ形式にする必要があるかは、PDF互換性を確認して決めてください。

プレビューと確定表示で同じ行分割・結合規則を使い、UI側とワーカー側で別の端点規則を持たないでください。

## 8.3 テスト

- 1文字選択。
- 同一行の複数文字が一つの帯になる。
- 文字間に透明な縦線が残らない。
- 複数行は行ごとに分かれる。
- 行頭・行末を欠落しない。
- 逆方向、非ゼロページ原点、傾斜文字。
- プレビュー、確定、コピー、ハイライト対象の一致。

# 9．右クリックメニュー

## 9.1 表示条件

次のいずれかを右クリックした場合に表示してください。

- 現在のテキスト選択範囲内。
- ハイライト注釈の表示領域上。

## 9.2 構成

```text
コピー
ハイライト注釈を作成
────────────────
注釈を編集
注釈を削除
```

- 「コピー」は現在の選択文字列をコピーする。
- 「ハイライト注釈を作成」は現在の選択範囲を使う。
- 注釈作成不可のPDFでは作成項目を無効化する。
- 編集・削除は、右クリック位置に対象注釈がある場合だけ有効にする。
- 右クリックで新しい選択を開始しない。
- 既存の選択表示を勝手に変更しない。

## 9.3 複数注釈

同じ位置に複数の注釈がある場合は、当面サブメニューで候補を表示し、対象を選択できるようにしてください。

```text
注釈を編集 >
    黄色・コメント先頭…
    青色・コメントなし

注釈を削除 >
    黄色・コメント先頭…
    青色・コメントなし
```

候補名は、コメントがあればその先頭、なければ注釈種別・色・ページ内で区別できる補助情報を使ってください。選択範囲本文の抽出へ必須依存させないでください。

## 9.4 変更に強い構造

少なくとも次の責務を分離してください。

1. ポインター座標からページ座標への変換。
2. 位置に存在する注釈候補の列挙。
3. 候補情報からUI表示モデルへの変換。
4. 候補から操作対象を決定する戦略。
5. 安定IDを使った編集・削除要求。

将来、最前面優先、最後に編集した注釈優先、一覧パネル、循環選択などへ変更できる境界を残してください。今回の実装はサブメニュー方式です。

# 10．ダブルクリックとヒットテスト

- ハイライト注釈をダブル左クリックすると編集UIを開く。
- 右クリックメニューと同じ編集開始処理を使う。
- 候補0件なら何もしない。
- 1件なら直接開く。
- 複数なら同じ候補決定戦略で一覧選択する。
- ズーム、スクロール、DPI、ページ原点、回転を考慮する。
- 外接矩形だけで十分か、Quad単位が必要かを実データで確認する。
- 許容値を使う場合は誤選択しないことをテストする。

# 11．編集対象と注釈モデル

## 11.1 今回の対象

完全な編集対象はハイライト注釈です。

- LunaPDFで現在の起動中に作成した未保存ハイライト。
- LunaPDFで作成し保存済みのハイライト。
- 他のPDFソフトで作成された既存ハイライト。

## 11.2 今回の対象外

- 下線、取り消し線、波線。
- 付箋・テキスト注釈。
- 図形、インク、リンク、フォーム、署名。

ただし、将来これらも編集できるようにしたいため、注釈の識別、列挙、ヒットテスト、候補選択、編集UI状態、Undo契約をハイライト専用の一枚岩にしないでください。

内部では必要に応じて次を表現できるようにしてください。

- 安定した注釈ID。
- 文書ID、ページ、revision。
- 注釈種別。
- Quadまたはアンカーgeometry。
- コメント／内容。
- 色。
- 編集・削除可能性。
- 種類固有の編集フィールド。

未使用の注釈種別のダミー実装は追加しないでください。

# 12．既存注釈の列挙・識別・読取

少なくともハイライトについて次を行えるようにしてください。

- ページ単位または必要範囲で列挙する。
- 安定IDを取得する。
- Quadまたは表示領域を取得する。
- 現在色を取得する。
- コメントを取得する。
- 編集・削除可能性を判定する。
- 更新後に同じ注釈を再識別する。

xref、オブジェクト番号、バインディング提供IDなど、利用可能な識別方法を調査してください。ページ内配列順だけを永続IDにしないでください。保存・再読込でIDが変わる場合は有効範囲を明示してください。

次も確認してください。

- 読取専用ファイル。
- 注釈権限がないPDF。
- 電子署名を含むPDF。
- 暗号化・権限制限。
- 外部ソフト固有の外観ストリーム。

更新できない場合はエラーを返し、別注釈の新規作成へ黙ってフォールバックしないでください。

# 13．注釈編集オーバーレイ

## 13.1 採用方式

当面は、アプリケーションウィンドウ右端に固定するオーバーレイ型を採用します。

- PDF表示領域の上へ重ねる。
- レイアウト分割へ参加させない。
- PDF中央領域の幅・高さを縮めない。
- 開閉時にFitWidth／FitPageの基準rectを変えない。
- 開閉時に倍率、現在ページ、スクロール位置、中心アンカーを変えない。
- 開閉だけで描画世代を更新しない。
- 左側のアウトライン／サムネイル用サイドバーとは独立させる。
- 左サイドバーと同時に表示できる。
- 全画面入力遮断領域を設けない。

```text
┌────────────┬────────────────────────────────────┐
│ 左サイド   │                                    │
│ 目次       │             PDF表示                │
│ サムネイル │                         ┌────────┐ │
│            │                         │注釈編集│ │
│            │                         │        │ │
│            │                         └────────┘ │
└────────────┴────────────────────────────────────┘
```

PDFの一部を覆って構いません。覆わないために中央領域を縮小しないでください。

## 13.2 開閉と本体操作

開く操作：

- 注釈のダブル左クリック。
- 「注釈を編集」。

閉じる操作：

- 明示的な閉じるボタン。
- 保存・破棄後の適切な操作。
- Escapeはコメント入力、色候補、候補選択、オーバーレイ本体の優先順位を整理する。

外側クリックで必ず閉じる必要はありません。PDFを操作しただけで長文編集中のUIが消えない方を優先してください。

オーバーレイ外では、PDFのスクロール、ズーム、ページ移動、タブ切替、テキスト選択、別注釈選択、左サイドバー操作を可能にしてください。

オーバーレイ上では入力欄、色選択、ボタン、内部スクロールを優先し、背後へ同じクリックやホイールを二重送信しないでください。

## 13.3 将来の自由移動式への拡張

今回は右端固定だけを実装しますが、将来ドラッグ移動できるフローティングパネルへ変更できる構造にしてください。

次を分離してください。

- 編集対象ID。
- 読取内容。
- 編集中バッファ。
- 保存・破棄・削除。
- 表示状態。
- 配置方針。
- 位置とサイズ。
- 右端固定／自由移動の配置モード。

編集フォームやPDF更新処理を右端座標へ直接依存させないでください。

今回実装しないもの：

- ドラッグ移動、リサイズ、位置保存。
- 別OSウィンドウへの切り離し。
- マルチモニター配置。

狭いウィンドウでもオーバーレイを画面内に収め、必要なら内部スクロールを使ってください。狭い場合にSidePanelや下部Panelへ自動変更しないでください。

# 14．注釈編集フォーム

## 14.1 レイアウト

コメントを色設定より上に置いてください。

```text
┌──────────────────────────────┐
│ 注釈の編集                ×  │
├──────────────────────────────┤
│ コメント／メモ                │
│ ┌──────────────────────────┐ │
│ │                          │ │
│ │ コメント入力欄            │ │
│ │                          │ │
│ └──────────────────────────┘ │
│                              │
│ 色                           │
│ [ ● 現在の色            ▼ ] │
│                              │
│ [保存] [変更を破棄]          │
│                              │
│ ───────────────────────────  │
│ [注釈を削除]                 │
└──────────────────────────────┘
```

## 14.2 コメント

- 複数行入力。
- PDF注釈の標準的なコメント／内容フィールドを調査し、互換性のある方法で読み書きする。
- 既存コメントは入力欄へ表示する。
- コメントなしは空欄にする。
- 選択範囲本文を表示しない。
- 選択範囲本文をプレースホルダーやコメントとして保存しない。
- 日本語、半角英数字、改行を保存・再読込できる。
- 入力欄にフォーカスがある場合は文字編集ショートカットを優先する。

## 14.3 色

通常は現在色だけを示し、クリック時に候補を展開してください。

```text
色
[ ● 黄色                ▼ ]
```

```text
┌────────────────────────┐
│ ● 黄色                 │
│ ● 緑色                 │
│ ● 青色                 │
│ ● 赤色                 │
│ ● 紫色                 │
│ ────────────────────── │
│ 任意の色を選択…        │
└────────────────────────┘
```

- 現在色を色見本と名称で示す。
- プリセット色を選べる。
- 任意色用カラーピッカーを開ける。
- 候補展開でPDF中央領域をリフローさせない。
- 背後へクリックを二重送信しない。
- 外部注釈の色を読めない場合は推測値を保存しない。
- 透明度は今回の明示的編集項目にしない。既存透明度を維持できるか確認し、勝手に固定値へ変えない。
- プリセットや表示名を後から変更しやすくする。

## 14.4 保存・破棄

- 「保存」でコメントと色を対象注釈へ反映する。
- 「変更を破棄」で編集開始時または最後の保存状態へ戻す。
- 入力のたびにPDFファイルへ直接保存しない。
- 編集バッファとPDF内の確定状態を分ける。
- dirty、revision、保存確認、描画更新へ反映する。
- 必要なページや注釈キャッシュだけを更新し、無関係な全タブを再描画しない。

未保存編集がある状態で別注釈・別タブを選ぶ細部は、現行方針を確認して決めてください。ただし、無言破棄、暗黙の自動保存、全画面モーダルは禁止します。オーバーレイ内の保存・破棄または非モーダルな状態表示で解決し、採用した状態遷移をテスト・報告してください。

## 14.5 削除

- フォーム下部に「注釈を削除」を置く。
- 保存・破棄から視覚的に分離する。
- コンテキストメニューと同じバックエンド処理を使う。
- 安定IDで対象を指定する。
- 他注釈を誤削除しない。
- 削除不可の場合は無効化または明確なエラーを出す。
- 削除後に表示、dirty、revision、保存確認を更新する。

即時削除ならUndoで確実に復元できることをテストしてください。確認を入れる場合も全画面モーダルにしないでください。

# 15．編集履歴とUndo

既存の汎用編集履歴を次へ拡張してください。

- ハイライト作成。
- コメント変更。
- 色変更。
- 注釈削除。

コメントと色を一度の保存で変更した場合は、自然な一つのUndo単位にまとめることを検討してください。具体的な履歴形式は現行`EditAction`とMuPDF APIを確認して決めてください。

- 別タブの注釈を変更しない。
- 保存・再読込後に無効IDを使わない。
- 外部作成注釈も安全にUndoできるようにする。
- 元コメント、色、geometry、必要な外観情報を復元する。
- 復元不能な情報を推測して成功扱いしない。
- `Ctrl+Z`と「編集 → 元に戻す」を維持する。
- コメント入力欄ではTextEdit自身のUndoを優先する。

# 16．保存と互換性

- コメント変更、色変更、削除をPDFへ保存する。
- 保存後にLunaPDFで再読込し、変更が残ることを確認する。
- 外部PDFビューアーでも開けることを確認する。
- 元fixtureを直接変更せず、一時コピーで検証する。
- qpdfなど既存の構文検査を利用できる場合は使う。
- 注釈件数、コメント、色、削除結果を保存前後で比較する。
- 外部ソフト作成ハイライトのコメント変更、色変更、削除を確認する。
- 外観ストリーム再生成で見た目が変わる場合は、その内容と制約を報告する。
- 編集不能な構造では理由を判定し、無効化またはエラーにする。

# 17．状態整合性

- 古い注釈列挙結果を新しいrevisionへ適用しない。
- タブ切替後の結果を別タブへ適用しない。
- 編集対象IDを文書ID、ページ、revisionと対応づける。
- 削除後の古い候補一覧から同じIDを再選択しない。
- 保存・再読込後に古い編集バッファを適用しない。
- テキスト選択generationと注釈編集状態を混同しない。
- オーバーレイを開いたままズーム、スクロール、ページ移動しても編集対象が別注釈へ変わらない。

# 18．入力・フォーカス競合

コメント入力中：

- 日本語IMEが動作する。
- Enterは改行。
- `Ctrl+C/V/X/Z`は入力欄を優先する。
- ページ移動、検索、PDF編集ショートカットが入力を奪わない。
- ホイールはオーバーレイ内部を優先し、PDF遷移へ流さない。

PDF操作中：

- オーバーレイ外ではスクロール、選択、ズームを維持する。
- オーバーレイ上のクリックを背後へ送らない。
- 色候補のクリックをPDFへ送らない。
- コンテキストメニューを開く右クリックで選択を開始しない。
- 注釈ダブルクリックでテキスト選択を確定しない。
