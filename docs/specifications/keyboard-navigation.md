# PDF キーボードナビゲーション仕様

この文書は矢印キー操作の正式仕様である。**矢印キー操作は実装確認**であり、末尾に記載した合成イベントによるヘッドレステストを実行している。GUI／OS の実機入力は未検証である。

## キー割り当て

| キー | 連続表示 | 単ページ表示 | 採用状況 | 実装状況 |
| --- | --- | --- | --- | --- |
| ← | 前ページへ移動 | 前ページへ移動 | 採用 | 実装確認 |
| → | 次ページへ移動 | 次ページへ移動 | 採用 | 実装確認 |
| ↑ | 文書内を上方向へ連続スクロール | 現在ページ内を上方向へスクロールし、上端での押下または有効なキーリピートで前ページへ移動 | 採用 | 実装確認 |
| ↓ | 文書内を下方向へ連続スクロール | 現在ページ内を下方向へスクロールし、下端での押下または有効なキーリピートで次ページへ移動 | 採用 | 実装確認 |
| PageUp | 前ページへ移動 | 前ページへ移動 | 既存仕様を維持 | 実装確認 |
| PageDown | 次ページへ移動 | 次ページへ移動 | 既存仕様を維持 | 実装確認 |

修飾キーなしの矢印キーは、同じ文書・表示モードで受け付けた押下の OS キーリピートも操作に使い、repeat イベント1回につき1回だけ操作する。単ページ表示でページ全体が縦方向に収まり、上下にスクロールできない場合は、↑ で前ページ、↓ で次ページへ移動する。拡大中にページ端へ到達させたイベントではページを跨がず、端の位置から届いた次の押下または有効なキーリピートで移動する。

## ページ位置と押下の扱い

- 連続表示の ↑／↓ はページ境界を越えても連続スクロールを続け、ページ単位のジャンプをしない。
- 単ページ表示で拡大中は、ページ内のスクロールを優先する。
- 前ページへ移動した後は移動先の下端側、次ページへ移動した後は上端側から表示を始める。既存の単ページ表示のホイール遷移と整合させる。
- 先頭ページより前、最終ページより後へは進まない。
- ←／→ は押下またはその押下が所有する OS キーリピートのイベントごとに1ページだけを移動する。先頭・末尾で止まり、ページ数を越えない。
- ↑／↓ は連続表示ではキーリピートによる連続スクロールを許容し、ページ境界を越えてもページ単位のジャンプをしない。
- ↑／↓ は単ページ表示でページ内スクロールを優先する。開始時に端でなかったイベントがスクロールして端へ到達しても、そのイベントではページを跨がず、端にいる状態で届いた次の押下または有効なキーリピートで1ページ移動する。
- ページ全体が縦に収まる単ページ表示では、↑／↓ の各押下・有効なキーリピートで前後1ページ移動する。
- キーを離した後の新しい押下も1回の操作として受け付ける。repeat イベントは同じ文書・表示モードで受け付けた先行押下に限り、タブ・ペイン・表示モード・入力所有者・ウィンドウフォーカスの変更で所有状態が切れた後の repeat は操作に使わない。
- 1回あたりのスクロール距離やキーリピートの時間は、この仕様では固定しない。

## フォーカスと入力の優先順位

- 検索欄、ページ番号欄、注釈コメント欄などでテキストを編集中は、文字編集側のキー操作を優先する。
- IME の変換候補選択や文字列内のカーソル移動を PDF 操作として横取りしない。
- モーダルダイアログまたはメニューの操作中は、背後の PDF ペインへ矢印キーを送らない。
- 入力先が不明なフォーカスも入力側に譲り、注釈エディターや候補ピッカーの表示中も PDF を操作しない。
- 分割表示では、左右分割・上下分割のどちらでもフォーカス中の PDF ペインだけを操作する。
- 対象は修飾キーを伴わない矢印キーに限る。Ctrl、Shift、Alt との組み合わせを新しい割り当てにしない。

## 既存キーとの関係

PageUp と PageDown の既存仕様は維持する。現行実装では、テキスト入力にフォーカスがない場合、PageUp／PageDown が前後ページへの移動処理を呼び出す。←／→ は、この既存処理と同じページ選択および文書境界の扱いを使う。ホイールとツールバーのページ移動も維持する。

[src/app.rs](../../src/app.rs) の handle_arrow_navigation は、メニューとツールバーの構築後に入力所有権を確認する。PageUp／PageDown、ホイール、ポインター操作、明示的なパン、自動スクロールと競合したフレームは、既存操作を優先する。連続表示のページ移動・アンカー復元も上下キーより優先する。単ページ表示では復元した位置を開始位置として扱い、前フレームのページ遷移アンカーが残っていても押下または所有したキーリピートを受け付ける。

[src/app/navigation.rs](../../src/app/navigation.rs) の ArrowNavigationState は Event::Key.repeat と解放イベントを区別し、同じ文書・表示モードで受け付けた押下のリピートを四方向すべての操作に使う。タブ・ペイン・表示モード・入力所有者の変更とウィンドウフォーカス喪失で押下状態を破棄し、同一フレームの重複処理を防ぐ。ScrollArea の確定した offset と可視サイズからスクロール上限を求め、保存状態と表示アンカーを同じ座標に更新する。単ページの端判定はイベント開始位置を基準とし、押下または repeat によるスクロールで端へ到達しても、そのイベントでページを跨がない。

## 適合確認の範囲

- 連続表示と単ページ表示の双方で、←／→ の押下と所有したキーリピートが前後1ページずつ移動し、先頭・末尾を越えない。
- 連続表示で ↑／↓ の押下・リピートが連続スクロールし、ページ境界でジャンプしない。
- 単ページ表示で、ページ内スクロール、端へ到達するイベント、端から次の repeat による遷移、遷移後の上下端の位置を確認する。
- ページ全体が縦に収まる表示倍率では、↑／↓ の押下・リピートが1イベントにつき1ページ移動する。
- キー解放後の再押下と、タブ・ペイン・表示モード・入力所有者・ウィンドウフォーカスの変更後に届く repeat の扱いを確認する。
- 検索欄、ページ番号欄、注釈編集欄、IME 変換中、モーダル、メニューで入力先が保護される。
- 左右分割と上下分割のそれぞれで、フォーカス中のペインだけが操作される。
- PageUp／PageDown、ホイール、ツールバーのページ移動を回帰確認する。

現行実装の確認箇所：[src/app.rs](../../src/app.rs) の handle_shortcuts、handle_arrow_navigation、central_panel、continuous_view、single_page_view、move_page、jump_to_single_page_edge、[src/app/navigation.rs](../../src/app/navigation.rs) の ArrowNavigationState、scroll_area_state_id、adjacent_page_index、[src/app/search.rs](../../src/app/search.rs) の検索状態、[src/ui/annotation_editor.rs](../../src/ui/annotation_editor.rs) のコメント入力。
